# 시연 시나리오 스크립트 (TTS 제작용)

심사위원은 배포 URL 에 접속해 마이크 없이 서비스를 본다. 그래서 상담 음성을 TTS 로 미리 만들어 두고, 그 음성 파일 하나를 서버로 흘려 STT 부터 판정까지 실제 경로를 태운다. 이 문서는 그 음성의 대본이고, 옆의 `preset-*/script.json` 이 같은 내용의 기계용 사본이다.

팀 합의(2026-09-02) 로 정한 제작·재생 방식은 다음과 같다.

| 단계 | 담당 | 입력 → 출력 |
| --- | --- | --- |
| 대본 | M3 (이 문서) | `script.json` 의 `lines[]`. 줄마다 화자·시각·대사·TTS 발음용 문장·기대 판정 |
| TTS | R5 | 줄마다 클립 하나(`<id>.wav`). 화자별로 다른 음성 |
| 조립 | R5 | 클립을 `start_ms` 타임라인대로 이어 붙여 **단일 파일** `audio.wav` (16kHz · mono · PCM16) |
| 재생 | M1 서버 | `audio.wav` 를 실시간 속도로 STT 에 스트리밍(`replay` 모드) |
| 화자 | M1 서버 | STT 의 화자 분리(diarization: 목소리 차이로 "누가 말했나" 를 구간별로 나누는 기능) 결과를 `teller`·`customer` 로 매핑 |

화자 분리와 매핑은 서버 담당 몫이다. 이 문서는 대본과 조립 규격까지만 정한다.

**대본이 진실 원천이다.** `preset-dep-a/script.json` 에서 계약 fixture `events_scenario_a.json`(trace 재생·리포트·접기 테스트의 입력)을 `back/scripts/gen_scenario_trace.py` 로 만든다. 대사를 바꾸면 `script.json` 을 고치고 → 생성기를 돌려 fixture 를 다시 만들고 → `contracts/validate.py` 와 `pytest` 로 판정 케이스·WS 메시지·엔진 테스트가 같은 대사를 보고 있는지 확인한다. 어느 한쪽만 고치면 시연 화면과 테스트가 서로 다른 상담을 말한다.

| 프리셋 | 팩 | 길이 | 장면 |
| --- | --- | --- | --- |
| `preset-dep-a` | `DEP-2026.08-v6` (ICBC 원화정기예금) | 2분 28초 | 정기예금 중도해지 상담. 기본 시연 경로 |
| `preset-loan-b` | `LOAN-2026.08-v7` (하나은행 가계 신용대출) | 2분 07초 | 신용대출 금리·한도 안내. 심화 경로 |
| `preset-loan-c` | `LOAN-2026.08-v7` (하나은행 가계 신용대출) | 약 2분 37초(추정. TTS 뒤 확정) | 대환 문자 받은 기존 고객. 대출빙자 위험 신호 · 2026-09-05 추가 항목 4건 고지 · 숫자 오류 · 서류 안내. **음원 미제작** |

모든 인물은 가상이다. 화면에 "시연 시나리오" 표시를 상시 띄운다(기획 16장 리스크 4).

## 1. 대본이 화자 분리를 돕기 위해 지킨 것

| 규칙 | 이유 |
| --- | --- |
| 은행원은 남성, 고객은 여성 음성 | 목소리 차이가 클수록 화자 분리가 정확함 `[관례]` |
| 화자가 바뀌는 자리마다 무음 1초 이상(`audio.min_gap_ms`) | 두 화자의 말이 붙으면 STT 가 한 발화로 합쳐 내고, 그러면 문장 단위로 갈라도 화자가 섞임 |
| 같은 화자가 연속으로 말하는 줄은 `speaker` 열이 진실 | 화자 분리 결과와 대조할 때 쓰는 정답. `diarization_hint.turn_order` 참조 |
| 첫 화자는 두 시나리오 모두 고객 | 서버가 "첫 화자 번호 = customer" 같은 단순 규칙을 쓸 수 있게. `diarization_hint.first_speaker` |
| 고객 대사는 되물음 장면 외에 물음표로 끝내지 않음 | 4.2 참조 |

**화자 매핑이 틀리면 무엇이 깨지나.** 위험 신호(`risk`)와 되물음(`comprehension`)은 고객 발화만 보고([tiers/l1/gate.py](../../back/engine/tiers/l1/gate.py)), 필수 고지와 금지 발언은 은행원 발화만 본다. 고객 줄이 은행원으로 붙으면 2:08 의 위험 신호 경보가 사라지고, 반대면 은행원의 고지가 미고지로 남는다.

## 3. 시나리오 B · 가계 신용대출 금리·한도 안내 (`preset-loan-b`)

기획 9장 B 는 주택담보대출 장면이지만 발행된 대출 팩은 가계 신용대출 하나다. 그래서 대사를 그 팩의 항목에 맞춰 신용대출 상담으로 쓴다. 주담대 고유 항목(LTV·근저당)과 구비서류 안내는 팩에 없어 넣지 않는다(5장 참조).

`gen_scenario_trace.py` 가 대본 A 를 서버의 문장 분리(`server/services/stt/assembler.py` 의 `utterances`)를 거쳐 실제 엔진(L0 → L1 → L2, `intfloat/multilingual-e5-small` 임베더, LLM 없음)에 순서대로 넣고, L3 몫은 대본의 `l3` 주석대로 넣어 fixture 48건을 만들었다. 대본 B 는 같은 방식의 세션 스크래치 하네스로 확인했다. STT 를 거치지 않은 정답 전사와 정답 화자 기준이다.

| 확인된 것 | 값 |
| --- | --- |
| A 종료 상태 | met 4 · partial 1 (`PRO-001`, 합산) · unmet 1 (`LIM-001`) · `BAN-001` violated(L3 주석) · 경보 3 · 채택 2. `validate.py` 3층 통과, 엔진 접기·재생 테스트 통과 |
| A 숫자 | "세율은 14%" → `TAX-001` met + 경보(설명서 15.4%). "세율은 15.4%" → 경보 없음 |
| A 금지 발언 L2 예시 유사도 | "만기 지나도 금리가 그대로 유지되니까 그냥 두셔도 돼요" 0.76 (임계 0.5) |
| A 위험 신호 | L1 정규식(`딸이 알려준`) 적중, critical |
| A 산식 | "약정이율에 예치 기간별 차감률을 곱해서 … 절반" → `INT-002` met (L1 `차감률`). 숫자 대조 없음 |

### 4.2 대사를 쓸 때 지킨 규칙 (실측에서 나온 것)

| 규칙 | 이유 |
| --- | --- |
| 고객 대사는 되물음 장면 외에 **물음표로 끝내지 않는다** | 엔진 기본 되물음 패턴에 `\?\s*$` 가 있어, 물음표로 끝나는 고객 발화는 전부 되물음으로 잡히고 이미 설명된 항목 중 하나에 재진술 카드가 붙는다 |
| "네?" 를 **독립 문장으로 두지 않는다** ("네에, …" 로 이어 쓴다) | 서버가 `?` 뒤에서 문장을 나누므로 "네?" 만 따로 판정된다. 유사도가 전부 0 인데도 되물음 대상이 첫 항목으로 잡혀 엉뚱한 재진술 카드가 떴다(실측) |
| 은행원 대사 한 문장에 **한 항목만** 담는다 | 서버가 마침표 단위로 나눠 판정한다 |
| 요소가 하나뿐인 키워드 언급은 판정되지 않는다 | `matcher.required_verdict` 가 요소 1개짜리 일반 키워드 히트를 "주제 언급" 으로 보고 넘긴다. 단 그 항목의 숫자가 같은 문장에 있으면 판정한다(0:30 의 세율이 그 경우) |
| partial 을 남기려면 요소를 **정확히 하나** 빼고 말한다 | `PRO-001` 은 '합산'·'합쳐'·'합해' 중 하나가 들어가면 met 이 된다. 그래서 "원금과 이자 포함" 으로 썼다 |
| 정정 문장에서 금지 예시의 단어를 다시 쓰지 않는다 | "상환방식은 고객님이 선택하실 수 있습니다" 는 금지 예시와 0.66 겹쳐 재경보 위험. "갚는 방법" 으로 바꿨다 |
| 정정할 때 다른 숫자를 함께 말하지 않는다 | 2:00 에 "15.4%" 만 말한다. "14% 에 지방소득세 1.4%" 를 덧붙이면 그 둘도 세율 사실과 대조돼 경보가 뜬다 |

## 5. 알려진 제약

| 제약 | 내용 | 영향 |
| --- | --- | --- |
| 화자 분리 | 서버가 STT 화자 분리 옵션을 켜고 번호를 `teller`·`customer` 로 매핑해야 한다. 현재 서버는 오디오 경로의 화자를 전부 `teller` 로 고정(`stt/session.py`) | 서버 작업 전에는 고객 줄의 위험 신호·되물음이 뜨지 않음 |
| L3 의존 | 넛지, violated 확정, comprehension confirmed, 카드 채택 기록은 LLM 심판이 붙어야 나온다 | `APP_LLM_MODEL` 이 비면 그 장면이 빠진다. 배포 전 확인 |
| 산식 판단 | 중도해지이율·만기후이자율의 비율(`약정이율×0.5`)은 숫자 대조가 아니라 L3 몫 | 은행원이 "절반" 을 "70%" 로 잘못 말해도 L1·L2 는 경보를 내지 않음. L3 가 근거 문장과 대조해야 함 |
| 용어 밀도(⑧) | 최근 8발화 창 안 은행원 발화의 팩 `jargon_terms` 출현 수로 잼(`engine/state/term_density.py`, 2026-09-03 dev 병합). 3개 이상이면 high, 은행원 발화 3턴 동안 0개면 low | 대본 A 는 0:37 부터 high 로 올라가 1:17 근처에서 low·normal 을 스치고 1:37 이후 다시 high. 경보가 아니라 `progress.term_density` 상태 표시 |
| 대출 팩 | 주담대가 아니라 신용대출 팩. 서류 항목(`LOAN-DOC-001`)은 2026-09-05 에 BEST 신용대출 상품 공시 스냅샷(원천 08)을 근거로 v6 에 실림 | B 의 B16 대사("신분증과 소득 증빙 서류")는 ④ 서류 카드와 대조할 수 있게 됐지만 대사 자체는 아직 안 고침. LTV·근저당은 주담대 팩 몫 |
| 서버 프리셋 | `GET /presets` 가 `assets/scenarios/*/script.json` 을 읽어 대본 하나를 프리셋 하나로 냄(`server/services/presets.py`, 2026-09-03 dev 병합). `preset_id`·`title`·`mode`·`product_code`·`pack_version`·`customer_profile`·`duration_ms` 를 그대로 쓰고, `lines[].expect` 의 둘째 토큰(`number_mismatch`·`rephrase` 등)을 세어 `expected_highlights` 를 만듦 | **`expect` 문자열의 앞 두 토큰(`alert <type>` / `assist <type>`)은 서버가 읽는 형식이 됨.** 바꾸면 심사위원 화면의 '볼 것' 안내가 바뀐다. `audio.wav` 가 없으면 `audio_ref` 를 내지 않아 재생 버튼이 켜지지 않음 |

## 6. DB 적재 (첫 배포와 팩 재발행 뒤)

2026-09-03 기준 배포된 서버·DB 는 아직 없다. 처음 띄울 때 `make up` 다음에 `make seed` 를 한 번 돌린다. 저장소의 팩 파일 전부(`contracts/fixtures/rulepack_*.json`)와 시연 A 이벤트 48건을 DB 에 넣는다.

- 팩 판정 자체는 DB 가 비어도 돈다. 서버가 파일로 내려가고(`DbThenFilePackSource`) L2 임베딩은 메모리에서 즉석 계산한다. 그러나 `GET /packs`·`GET /packs/{version}` 은 DB 만 읽어 빈 목록·404 가 되고, trace 재생(기획 11.4)은 저장된 이벤트가 없으면 재생할 것이 없다. `make seed` 는 이 둘을 채운다
- 팩이 DB 에 들어간 뒤로는 그 버전은 DB 가 파일을 이긴다. 파일만 고치면 화면은 옛 값을 보여주므로, 팩을 재발행하면 `make seed` 를 다시 돈다(`--replace` 라 같은 버전을 덮어쓴다)
- `--unsigned` 는 fixtures 파일이 서명 없는 발행물이라 필요하다. 서명 적재(`compile` envelope + `RULEPACK_APPROVAL_HMAC_KEY`)는 `rulepack/docs/PIPELINE.md`
- 프리셋 목록은 `script.json` 의 `pack_version` 을 그대로 내므로 따로 넣거나 넘길 것은 없다
