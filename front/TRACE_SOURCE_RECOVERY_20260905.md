# TRACE 이력의 다시 재생

## 확인한 원인

사용자가 지적한 것은 목록 건수가 아니라 `TRACE 이력이 아닌 원본 상담에서 재생해 주세요.`라는 일괄 차단이었다. 이번 변경은 목록의 디자인·페이지 수를 바꾸지 않는다.

- 수정 전 로컬 API와 Docker PostgreSQL에는 세션 56개가 있었다. TRACE는 12개, 원본 LIVE/REPLAY/TEXT의 발화는 각각 29/37/42개였다. 원본 발화가 사라진 상태는 아니었다.
- 읽기 전용 SQL에서 기존 TRACE 12개 모두 `source_session_id IS NULL`, TRACE 발화는 0건이었다. API 이벤트도 시작/종료 기록뿐이었다. TRACE의 빈 이벤트를 새 재생 대상으로 넘기는 것만으로는 이전 상담이 재생되지 않는다.
- 이전 프론트는 이를 `mode === trace`로 일괄 차단했다. 원본을 찾는 경로 없는 비활성 버튼은 잘못된 UX였다.

## 수정한 경로

1. TRACE 이력에도 `TRACE 재생` 버튼을 활성화한다. 실행 중 상담의 종료/다른 활성 상담 보호 규칙은 유지한다.
2. 이 브라우저에서 새 TRACE를 만들 때, 성공한 생성 요청의 정확한 `TRACE ID → source_session_id`를 기억한다. 새로고침 후에도 이를 따라 원본 ID로 새 TRACE를 생성한다. 판정·발화·고객정보는 저장하지 않는다.
3. 자체 저장 발화·판정 등이 있는 TRACE도 모드만으로 막지 않는다.
4. 연결과 자체 이벤트 모두 없는 기존 TRACE는 `재생할 상담 선택`을 연다. 동일 팩의 종료된 상담을 전 페이지 조회하고, 실제 저장 발화/판정 유무를 확인한다. 날짜·발화 미리보기·세션 ID 검색과 재생 버튼을 제공한다. API 실패는 빈 기록과 구분한다.
5. 사용자가 명시적으로 선택한 상담을 재생한다. 선택을 과거 TRACE의 실제 원본이었다고 추측하거나 DB에 역으로 기록하지 않는다.
6. 순환 연결·삭제된 원본은 선택 경로로 돌아오며 네트워크 실패는 재시도할 수 있는 오류로 표시한다. 빈 대상을 새 TRACE로 생성하지 않는다.

## 경계와 한계

- 모든 수정은 `front/`만. 백엔드 Python·계약·DB 스키마·기존 기록은 수정하지 않았다.
- 브라우저 원본 연결 저장은 서버 DB의 누락을 고친 것이 아니다. 브라우저/사이트 데이터 삭제·다른 기기에는 전달되지 않는다. 그런 경우에도 선택창으로 재생 가능하다.
- 서버에 이미 누락된 과거 원본 ID를 날짜/상품명으로 추측하지 않는다. 과거 TRACE의 정확한 자동 재연결을 모든 기기에서 보장하려면 서버의 원본 ID 영구 저장/조회가 필요하다.
- 원본 타임스탬프 간격과 서버 TRACE 자동 종료 동작은 이번 변경 대상이 아니다.

## 검증

- TypeScript, 계약/PCM 검사, 랜딩 검사, 기존 세션 복구 단위 검사 통과.
- `node scripts/trace-source-unit.cjs`: 링크 복원, 빈 TRACE, 자체 이벤트 TRACE, 연결 사슬/순환, 404와 503 구분, 서버 목록 페이지 조회, 조회 실패 노출, 개인정보 없는 ID 저장, 저장소 차단 환경 검증.
- `node scripts/trace-source-qa.cjs`: 기존 로컬 QA TRACE에서 선택창 → 실제 원본 발화 미리보기 → 백엔드 WS 재생 → 종료 → 새로고침 → 방금 만든 TRACE 다시 재생까지 통과. 생성 요청의 `source_session_id`와 서버 발화 원문을 대조했다.
- 원본 상담 및 기존 TRACE 이벤트 JSON이 검사 전후 동일함을 확인. 새로 만든 QA 재생 2개만 종료했고 기록을 삭제하지 않았다.
- 선택창 320~1920px 10개 화면 조건에서 스크롤·영역 넘침·겹침 0, 브라우저 오류 0. PC/모바일 스크린샷 확인.
- 검사 산출물은 gitignore된 `front/qa-output/trace-source-qa.json`과 `trace-source-picker-*.png`.

## 첫 발화 전 로딩 화면

- TRACE에만 기존 대시보드 색상/서체의 로딩 화면을 표시한다. `ready`·`partial`·판정·진행률 수신으로 해제하지 않고, 실제 최종 발화가 전사 목록에 들어오면 해제한다. 화자 필터와는 무관하다.
- 대기 중 재생 중지와 이력 이동을 제공한다. 연결 오류는 로딩 애니메이션 대신 오류·재연결 동작을 표시한다. 중지는 서버의 종료 확인을 기다린다.
- 생성 전에 원본 이벤트 전 페이지를 확인한다. 발화 없이 판정·안내만 있는 기록은 존재하지 않는 첫 발화를 기다리지 않고 기존 화면에서 안내한다. LIVE/TEXT/REPLAY의 시작 동작과 서버 재생 간격은 변경하지 않는다.
- `node scripts/trace-start-unit.cjs`: 최초 발화 조건, 다른 모드, 오류/중지 상태 렌더링, 무발화 기록 검증 통과.
- `QA_TRACE_LOADING=1 node scripts/trace-source-qa.cjs`: 실제 서버 WS 메시지를 테스트에서만 순서 보존 지연 전달하여 로딩 유지/첫 발화 전환 확인. 새로고침 후 재시작, 첫 발화 전 중지의 서버 저장, 원본 로그 불변, 선택창/로딩 화면 총 20개 크기 조건, 모션 감소 설정 검증 통과. 산출물 `front/qa-output/trace-loading-qa.json`.
