# REPLAY 음성·말풍선 동기화

## 적용 범위

기존 공개 시연 프리셋 `preset-dep-a`(ICBC 원화정기예금), `preset-loan-b`(하나은행 가계 신용대출)의 TTS 음원을 재사용한다. 추가 TTS 요청이나 마이크 사용은 없다. 백엔드·DB·계약은 변경하지 않는다. 새 REPLAY뿐 아니라 원본 시연 프리셋이 확인되는 기존 REPLAY 이력의 TRACE 재생에도 연결한다. LIVE, TEXT에는 시연 음원을 붙이지 않는다.

## 동작

1. `이력 → 시연 음원 → 음원 시연 시작`에서 브라우저 오디오 출력을 준비하고 선택한 서버 프리셋의 원본 WAV를 불러온다. 목록을 보기만 하면 재생하지 않는다.
2. 서버의 확정 `utterance`를 원본 시연 대사의 텍스트와 대조한다. 공백·문장부호를 정규화한 뒤 앞으로 진행하는 유일한 대사만 연결한다. 숫자를 바꾸거나 판정을 만들지 않는다.
3. 서버 말풍선을 화면에 반영한 직후 해당 원본 TTS 대사의 시작 구간을 재생한다. 다음 대사와 소리가 겹치지 않도록 순서를 유지한다. 서버 하트비트는 기다리지 않고 바로 응답한다.
4. STT가 같은 대사를 여러 메시지로 나누면 음성을 처음부터 반복하지 않는다. 불분명하거나 매칭되지 않는 발화는 서버 텍스트만 표시한다.
5. `기록 재생` 화면의 대화 상단에서 `소리 끄기 / 소리 켜기`로 음소거한다. 자동 재생 차단·음원 오류에는 다시 켜기/재시도 안내를 표시하며 서버 재생을 가로막지 않는다.
6. 재생 종료, 연결 끊김, 다른 서비스 탭 이동 시 음성을 멈춘다. `상담` 탭을 선택하면 활성 REPLAY/TRACE의 서버 종료를 확인한 뒤 새 상담 준비로 이동한다. 종료가 확인되지 않으면 오류·재연결 화면을 유지한다. 새 상담에서는 오디오 자원을 해제한다.

## 실제 상담과 기록 재생의 구분

- `상담`: 기본 입력은 LIVE 마이크 녹음이다. 상담 시작 후에도 녹음 버튼을 누르기 전에는 PCM을 보내지 않는다. 녹음 시작/중지는 사용자가 직접 누른다. TEXT는 명시적으로 선택해 입력하는 보조 방식이다. 상담 준비에서는 프리셋을 선택하거나 자동 재생하지 않는다.
- `이력 → 저장된 상담`: 기존 세션의 리포트와 TRACE를 연다. 실행 중인 REPLAY/TRACE는 `재생 이어보기`, LIVE/TEXT는 `상담 열기`로 구분한다.
- `이력 → 시연 음원`: 서버 `/presets`의 REPLAY·음원 참조가 있는 프리셋만 제공한다. 임의 시나리오는 만들지 않는다.
- REPLAY/TRACE는 `기록 재생` 제목을 사용하고 이력 메뉴를 활성화한다. LIVE/TEXT만 상담 메뉴를 활성화한다. 재생 화면에는 마이크 녹음 버튼이 없다.

### 용어 나열 발화 진단의 한계

신고된 용어 나열 문장은 예금 팩의 `jargon_terms`와 일치하며, 두 준비된 시연 대사에는 없다. 로컬에서 녹음 전 8초 동안 PCM·발화가 모두 0건이었고, 32초의 디지털 무음 녹음에서도 발화가 생성되지 않았다. 이는 해당 로컬 조건의 관찰이며, 실제 장치·배포 환경의 무음 오인식까지 해결했다는 뜻은 아니다. 프론트에서 서버 발화를 임의 삭제하거나 용어 목록으로 필터링하지 않았고 STT·백엔드는 변경하지 않았다.

대사 단위 동기화이며 단어별 자막 정렬은 아니다. 화면의 텍스트·화자·판정·진행률은 서버 응답 그대로다. 이력에서는 원본 REPLAY의 저장된 `session_started.preset_id`를 우선 사용한다. 없을 경우 이 브라우저가 해당 상담 생성 시 기록한 정확한 세션→프리셋 ID만 사용한다. 서로 충돌하는 서버 프리셋 ID나 출처 없는 녹음에는 음원을 붙이지 않는다. 상품이나 문장이 같다는 이유로 추측하지 않는다.

## 기존 DB 이력 검증

로컬의 `FIXT-SESS-0A`(ICBC 원화정기예금 · 2026-09-07 20:02 KST)는 시작 이벤트에 `preset-dep-a`가 저장되어 있다. `sessions.preset_id` 열과 세션 상세 API에는 이 값이 없지만 **이벤트 조회 API에서는 제공**된다. 최초 구현이 이 메타데이터를 누락해 새 상담만 음성 연결한 문제를 `history-audio.ts`로 수정했다.

이력 → 해당 REPLAY → TRACE 재생 순서로 실행하면, 기존 원본 이벤트를 서버가 재생하고 프론트가 대응하는 원본 ElevenLabs TTS 구간을 출력한다. 새 브라우저에서도 DB 이벤트 정보만으로 동작한다. 연결된 TRACE를 이 브라우저에서 다시 재생하면 기억한 원본 ID를 따라 동일하게 동작한다. 기존 연결 정보가 없는 TRACE는 기존 원본 상담 선택 흐름을 유지한다.

WAV 바이너리가 DB에 들어 있는 것은 아니다. DB의 시연 프리셋 참조와 저장소의 원본 WAV를 연결한다. 두 WAV 모두 지원하지만, 확인된 기존 DB 시연 참조는 위 예금 이력이며 음원 참조 없는 다른 과거 이력까지 자동 연결했다고 간주하지 않는다.

## 음원 배포와 갱신

현재 REST 계약에는 시연 음원 다운로드 경로가 없고 프론트 Docker 빌드 범위가 `front/`라서, 두 공개 가상 시연 음원만 `public/replay/`에 묶었다. WAV는 저장소 원본과 바이트 단위로 동일하다. manifest에는 재생 구간·텍스트·팩 버전·검증 해시만 포함하며 기대 판정·키는 포함하지 않는다. 기존 Dockerfile의 public 복사로 배포된다.

원본 시나리오가 갱신되면 `front/`에서 실행한다.

```sh
node scripts/prepare-replay-audio.cjs
node scripts/prepare-replay-audio.cjs --check
```

원본은 `assets/scenarios/<preset>/script.json`과 `audio.wav`다. 생성 스크립트는 알려진 대사 사이의 무음 꼬리만 재생 구간에서 제외하며 원본 WAV 자체는 수정하지 않는다.

## 검증

- `replay-audio-unit.cjs`: 두 프리셋 32개 대사 매칭, 말풍선 우선 반영, STT 분할 중복 방지, 순차 재생, 음소거, 중지/화면 전환, 복구, 자동 재생 차단, 음원·장치 오류.
- `replay-audio-qa.cjs`: 실제 로컬 서버로 두 REPLAY를 시작해 각 첫 두 대사의 원본 오프셋, 비무음 PCM, 재생 순간 서버 말풍선 표시, 음소거, 종료 확인. 생성한 검증 세션만 종료한다.
- `history-audio-unit.cjs`: 저장된 프리셋 우선, 브라우저 정보 없는 경우, 정확한 생성 정보 fallback, 출처 미확인/충돌 차단.
- `history-audio-qa.cjs`: 기존 DB 예금 이력 → 실제 TRACE의 첫 두 대사·음성, 로딩 해제 시점, 음소거·종료, 새로고침 후 TRACE 반복, 원본 이벤트 불변, 10개 화면 크기 검증.
- `consultation-mode-unit.cjs`: LIVE/TEXT와 REPLAY/TRACE의 화면·메뉴 분리, 상담 준비의 LIVE 기본값과 프리셋 옵션 제거.
- `consultation-mode-qa.cjs`: 실제 로컬 서버로 녹음 전 전사 없음, 가상 마이크에 넣은 공개 시연 WAV의 실제 STT, 녹음 중지, 이력에서만 명시적 재생, 상담 탭 전환 시 서버 종료 확인, 10개 화면 크기 검증. 검증용 신규 세션만 종료한다.
- `live-silence-diagnostic.cjs`: 녹음 전 대기와 디지털 무음 녹음의 PCM·발화 관찰. 실제 마이크 환경의 재현을 대신하지 않는다.
- 예금 상담 화면을 320×568부터 1920×1080까지 10개 크기로 검토: 내부/외부 스크롤, 겹침, 화면 밖 버튼 없음.
- 기존 TRACE 로딩·이력 복구·계약 테스트 및 TypeScript 검사, 프로덕션 빌드 통과.

실제 브라우저 QA는 첫 두 대사까지의 통합 검증이며 두 시나리오 전체의 단어별 정렬을 보장하는 테스트는 아니다.
