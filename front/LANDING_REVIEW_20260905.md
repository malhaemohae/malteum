# 랜딩 제품 쇼케이스 검토

## 요청 반영

- 01·03 카드의 의미 없는 파형/원형 장식과 기존 3열 카드 격자를 제거했다.
- 첫 화면은 헤드라인과 큰 상담 화면 비주얼, 이후는 상담 안내·근거 문서·종료 리포트의 좌우 교차 구성이다.
- 참고자료의 보라색/검은 배경 대신 말틈의 흰색·시안·잉크와 옅은 골드 포인트를 유지한다.
- 하단은 상담 준비 → 녹음 시작 → 리포트의 실제 진입 흐름과 공통 시작 CTA로 정리했다. 녹음·튜토리얼·환경 설정은 랜딩에서 실행하지 않는다.
- 보조 카드가 히어로 대화 글자를 덮지 않도록 별도 공간을 확보했다. 번호는 순서가 있는 이용 단계에만 남겼다.

## 구현 경계

- `components/marketing-showcase.tsx`와 `app/landing-showcase.css`가 현재 랜딩이다. 이전 `marketing-landing.tsx`는 교체했다. 기존 대시보드와 백엔드는 수정하지 않았다.
- 예시 대화·안내의 정본은 `back/contracts/fixtures/events_scenario_a.json`, `ws_messages.json`이다. 문서 원문과 페이지는 `rulepack_DEP-2026.08-v4.json`, 리포트 집계는 `ended.summary`가 출처다. 배포 컨텍스트가 `front/`뿐이므로 필요한 값만 `lib/landing-preview-data.json`에 두고 `landing-qa.cjs`가 원본과 동일한지 검사한다. 런타임에서 `back/` 파일을 직접 import하지 않는다.
- 모든 제품 비주얼에 ‘화면 예시’를 표기한다. 실제 사용자 세션 데이터나 서비스 성과 지표로 표시하지 않는다. 예시 데이터를 실제 상담 상태로 넣지 않는다.

## 확인

- 브라우저 DOM 기준: 1920, 1440, 1366, 1280, 1024, 820, 768, 624, 520, 390, 360, 320px 너비에서 가로 넘침, 주요 문구 넘침, 본문/비주얼 겹침, 보조 카드의 대화 가림이 없는지 확인했다. 비동기 창 크기 전환 후 실제 `innerWidth`를 기준으로 확인했다.
- 데스크톱 첫 화면, 상담 안내, 리포트와 390/320px 모바일을 스크린샷으로 검토했다. 시작 CTA가 실제 상담 준비 화면으로 이동하는 것을 확인했다.
- `node scripts/landing-qa.cjs`: 공식 시연 문구·원문 페이지·종료 집계, 예시 표기, 모든 앵커, 공통 CTA 및 랜딩에서 상담을 시작하지 않는 렌더링을 검사한다.
- TypeScript와 `.next-verify` 프로덕션 빌드 검증. 음성·TRACE 백엔드 기능 검증은 이번 랜딩 변경 범위가 아니다.
