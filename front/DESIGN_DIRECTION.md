# 말틈 프론트엔드 디자인 방향

> 상태: v0.9 방향 확정 · 단일 제품 폰트·카드 리본 제거·반응형 QA 반영
> 범위: `front/` 안의 웹 화면과 에셋
> 제품: 말틈
> 캐릭터: 바름이

## 1. 한 문장 방향

**쫀득한 컴플라이언스 케이스보드 + 따뜻한 안내자**

말틈은 금융 창구 상담 중 설명의무를 확인하고 근거를 남기는 도구다. 화면은 금융기관이 신뢰할 수 있을 만큼 정돈되고 정확해야 하며, 캐릭터 바름이는 은행원을 감시하는 존재가 아니라 상담을 돕는 안내자로 보여야 한다.

캐릭터는 친근함을 담당하고, 대시보드는 근거·상태·감사 기록을 담당한다. 첨부 레퍼런스의 장점인 기능별 카드, 즉시 읽히는 상태색, 작은 아이콘을 가져오되 금융 업무 화면에 맞게 장식을 절제한다. 모든 카드를 같은 둥근 흰 표면으로 만들지 않고, 진행 레일·개입·전사·체크리스트·근거의 역할에 따라 테두리와 강조 위치를 달리한다.

랜딩의 역할도 단순한 소개가 아니다. 랜딩은 **녹음으로 시작하기** 한 번을 중심으로 설계하고, 상품·모드·고객 라벨은 세션 설정 안으로 낮춘다. 사용자는 긴 회원가입이나 설명 페이지를 거치지 않고, **녹음·녹취 시작 → 실시간 전사 → 판정·근거 확인** 흐름을 바로 경험해야 한다.

## 2. 브랜드와 캐릭터

### 제품

- 표기명: **말틈**
- 영문 기술 식별자: `malteum`
- 핵심 메시지: 외우지 않아도, 빠뜨리지 않습니다
- 제품 프레임: 감시·처벌이 아닌 방어·지원

### 캐릭터

- 이름: **바름이**
- 공식 호칭: `말틈의 컴플라이언스 가이드, 바름이`
- 역할: 규정과 상담 발화를 연결하고, 설명서 기준을 차분하게 알려주는 조력자
- 로고 에셋: [`public/assets/malteum-logo.png`](public/assets/malteum-logo.png)
- 튜토리얼 에셋: [`public/assets/malteum-mascot.png`](public/assets/malteum-mascot.png)

### 바름이 사용 원칙

사용한다:

- 말틈 로고 안의 브랜드 캐릭터
- 랜딩에서 대시보드까지 핵심 기능을 설명하는 튜토리얼 대화창

사용하지 않는다:

- 위험 신호·금지 발언 카드 안의 웃는 얼굴
- 위반 상태를 희화화하는 장식
- 모든 화면에 반복 노출하는 워터마크
- 경보 아이콘을 캐릭터로 대체하는 방식

위험·위반 상태는 아이콘과 명확한 텍스트로 표현한다. 튜토리얼이 끝난 뒤의 랜딩·대시보드에는 캐릭터 이미지를 반복 노출하지 않는다.

## 3. 컬러 토큰

캐릭터에서 추출한 따뜻한 골드·브라운·시안을 브랜드 포인트로 사용하되, 금융기관용 화면의 기반은 깊은 네이비와 따뜻한 회백색으로 둔다.

| 토큰 | HEX | 역할 |
| --- | --- | --- |
| `--color-ink` | `#18333D` | 주요 텍스트, 사이드바, 주요 CTA |
| `--color-cyan` | `#55B4D0` | 활성 상태, 링크, 포커스, 보조 강조 |
| `--color-gold` | `#F0D080` | 로고·튜토리얼, 브랜드 포인트, 강조 배지 |
| `--color-brown` | `#704030` | 로고·일러스트 디테일 |
| `--color-canvas` | `#EEF3F2` | 전체 앱 배경 |
| `--color-surface` | `#FFFFFF` | 카드·패널 |
| `--color-border` | `#D7E3DF` | 구분선·카드 테두리 |
| `--color-met` | `#2D806F` | 고지 완료 |
| `--color-partial` | `#B27924` | 부분 고지 |
| `--color-violated` | `#B24A3F` | 금지 발언·숫자 오류 |
| `--color-risk` | `#753E5C` | 위험 신호 |

### 컬러 규칙

- 골드는 브랜드 컬러이지 경고 컬러가 아니다.
- `risk`와 `violated`는 서로 다른 색으로 구분한다.
- 색만으로 상태를 전달하지 않는다. 아이콘·라벨·텍스트를 함께 쓴다.
- 주요 버튼은 골드 바탕에 흰 글자를 넣지 않는다. 기본 CTA는 네이비 바탕과 흰 글자 또는 충분한 대비의 시안 조합을 사용한다.
- 화면 전체에 강한 그라디언트·글래스모피즘·네온을 사용하지 않는다. 필요한 곳의 미세한 표면색 차이와 그림자로 카드의 기능을 구분한다.

## 4. 타이포그래피

폰트는 장식보다 읽기 속도를 우선한다. 캐릭터성 강한 디스플레이 폰트는 사용하지 않고, 실제 금융 업무 제품에서 오래 읽어도 피로하지 않은 고딕을 기본으로 둔다.

- 화면 전체의 본문·버튼·폼·카드 설명·제목·수치·타임스탬프·상태 코드: `Pretendard`
- 폴백: `Pretendard`, `Apple SD Gothic Neo`, `system-ui`, `sans-serif`

Pretendard의 굵기와 크기로 정보 계층을 만들고, 별도 디스플레이 폰트나 모노스페이스로 화면을 꾸미지 않는다. 시간·진행률·수치는 `tabular-nums`로 열을 맞춘다.

## 5. 화면 구조

### 공통 앱 셸

```text
┌──────────────┬────────────────────────────────────────────┐
│ 말틈         │ 세션·상품·고객·모드·연결 상태               │
│              ├────────────────────────────────────────────┤
│ 상담         │ 녹음 → 전사 → 판정 → 근거 진행 상태         │
│              ├────────────────────────────────────────────┤
│              │ 핵심 개입 슬롯: 지금 가장 중요한 한 가지    │
│ 리포트       ├──────────────────────────┬─────────────────┤
│ 규정 팩      │ 실시간 전사               │ 필수 안내 상태  │
│ 문서         │                            │                 │
│ 이력         ├──────────────────────────┴─────────────────┤
│              │ 규정 질의 / 근거 원문 / 수동 입력            │
└──────────────┴────────────────────────────────────────────┘
```

- 왼쪽: 고정 네이비 사이드바
- 본문: 따뜻한 회백색 캔버스
- 카드: 따뜻한 흰색과 회백색 표면, 얇은 중립 테두리, 8~14px 중심의 낮은 radius, 낮은 강도의 그림자. 상단 그라디언트 띠나 장식 리본은 사용하지 않는다.
- 첫 화면의 시선은 녹음 상태와 중앙 개입 슬롯으로 모인다.
- 개입은 한 번에 하나만 크게 보여준다. 기본 상태에서는 화면이 조용해야 한다.

### Information Dashboard Design 적용

Stephen Few의 *Information Dashboard Design* 원칙을 말틈의 업무 흐름에 맞게 적용한다. 대시보드는 장식적인 그래프 모음이 아니라 상담 목표를 모니터링하는 단일 작업 화면이어야 한다. 따라서 정보는 `녹음 상태 → 현재 개입 → 상태 요약 → 전사·체크리스트 → 근거` 순서로 계층화하고, 차트·배지·색상은 판단에 직접 도움이 될 때만 사용한다.

- 가장 중요한 한 가지(현재 개입)는 가장 큰 면적과 높은 대비로 둔다.
- 녹음 위치와 처리 단계를 한 줄의 진행 레일로 묶어 현재 위치를 곁눈질로 읽게 한다.
- `고지 수`, `개입 필요`, `상담 상태`만 상단 요약에 남겨 KPI를 늘리지 않는다.
- 비교가 필요한 수치는 `말씀`과 `설명서 기준`을 같은 축에 두고, 장식용 차트 대신 직접 비교한다.
- 위험·금지·숫자 오류는 색상만으로 판정하지 않고 라벨과 문장을 함께 표시한다.

참고: [Why Most Dashboards Fail — Stephen Few / Perceptual Edge](https://www.perceptualedge.com/articles/misc/WhyMostDashboardsFail.pdf), [Information Dashboard Design outline](https://perceptualedge.com/images/Dashboard_Outline.pdf)

### 화면별 역할

| 화면 | 디자인 기준 |
| --- | --- |
| L0 랜딩 | 말틈 로고·핵심 메시지·녹음 시작 버튼을 한 화면에 배치. `녹음으로 시작하기`를 누르면 녹취 재생 또는 녹음 대시보드로 이동 |
| S1 상담 라이브 | 녹음·전사 진행 레일, 개입 슬롯, 필수 안내 체크리스트, 질의 입력. 6개 상태 변형을 같은 레이아웃 안에서 처리 |
| S2 종료 리포트 | 고지·부분 고지·위반을 요약하고, 항목별 근거·타임스탬프·발화 재생으로 연결 |
| S3 규정 팩 | 팩 목록, 버전, 항목 타입, 근거 조문, 쉬운 말, 개정 감지 |
| S4 문서 검수 | 업로드 → 추출 → 근거 스팬 검증 → 승인·발행. 근거 없는 자동 폐기 행을 숨기지 않음 |
| S5 세션 이력 | 세션 목록과 trace 재생. 날짜·상품·모드·결과를 빠르게 비교 |
| O1 근거 원문 | PDF 페이지·문장 하이라이트·항목 정보. S1·S2·S3 어디서든 열리는 오버레이 |

### S1 라이브 핵심 구성

1. 상단: `말틈`, 상담/리포트/규정 팩/문서/이력, 연결 상태, 녹음 상태, 모드
2. 녹음 레일: 녹음·전사·판정·근거 처리 단계와 현재 위치, 재생 위치
3. 상태 요약: 고지 수·개입 필요·상담 상태만 간결하게 표시
4. 중앙 개입 카드: 숫자 오류·위험 신호·재진술·역질문 등 현재 우선순위 한 건
5. 전사: 은행원·고객 화자를 구분하되, 원본 오디오와 partial 전사는 저장하지 않음
6. 필수 안내: `고지 / 부분 / 미고지`와 항목별 근거 진입
7. 하단: `근거 원문 보기`, 규정 질의, 필요 시 수동 체크

## 6. 랜딩 입력과 진입 흐름

### 랜딩의 단일 목적

랜딩은 제품을 길게 설명하는 페이지가 아니라 **녹음으로 첫 상담 세션을 바로 시작하는 입구**다. 로그인·회원가입·긴 설문·고객 라벨 입력을 첫 화면의 주 행동으로 두지 않는다.

```text
L0 랜딩
  └─ 녹음으로 시작하기
       ├─ replay (기본 · 준비된 녹취 재생)
       └─ live (고지 후 실시간 녹음)
  └─ 세션 설정 (선택)
       ├─ 상담 유형
       ├─ 실행 모드
       └─ 가상 고객 라벨
       ↓
녹음·녹취 상태 레일
       ↓
실시간 전사 → 판정 → 근거 확인
```

### 입력 항목

현재 시연에 필요한 최소 입력만 받는다.

| 입력 | 필수 | 기본값·동작 |
| --- | --- | --- |
| 상담 유형 | 필수 | `예적금 중도해지`를 기본 선택. `주택담보대출`도 선택 가능 |
| 실행 모드 | 필수 | `replay` 기본. `live` 선택 시 녹음 고지·마이크 상태 안내, `text`는 직접 입력 |
| 고객 정보 | 선택 | 실제 개인정보를 받지 않는다. 데모에서는 가상 고객 라벨만 사용 |

상담 유형과 모드는 기본 화면에서 노출을 줄이고 `세션 설정` 안에서만 조정한다. 기본값은 예적금 중도해지·REPLAY이며, 시연의 첫 행동은 녹음 버튼 하나로 고정한다.

녹음 버튼은 정적인 CTA가 아니라 준비 상태를 보여주는 작은 인터랙션이다. 버튼 안의 파형·링·상태 점은 녹음 대기 중임을 알리고, hover·active 상태는 시작 동작의 확신을 높인다. 장식용 애니메이션을 여러 개 흩뿌리지 않고, 녹음이라는 핵심 행동 주변에만 사용한다.

### 랜딩 레이아웃

```text
┌──────────────────────────────────────────────────────────────┐
│ 말틈                                      규정 팩  문서  이력 │
├──────────────────────────────┬───────────────────────────────┤
│ 외우지 않아도,                │ 상담 시작                      │
│ 빠뜨리지 않습니다             │                               │
│                              │ 상담 유형                       │
│ 규정에서 뽑은 항목을           │ [ 예적금 중도해지 ]             │
│ 상담 중에 하나씩 확인합니다.   │ [ 주택담보대출 ]                 │
│                              │                               │
│             녹음 → 전사 → 판정 → 근거 │ 녹음으로 시작하기             │
│             (검증 흐름 그래픽) │                               │
│                              │ [ 상담 시작하기 ]                │
└──────────────────────────────┴───────────────────────────────┘
```

- 왼쪽은 제품의 이유와 녹음·전사·판정·근거 흐름을 보여주는 브랜드 영역이다.
- 오른쪽은 입력 폼이 아니라 `녹음으로 시작하기`를 중심으로 한 세션 시작 카드다.
- 상담 유형·실행 모드·고객 라벨은 접힌 `세션 설정`에서 선택적으로 바꾼다.
- 대시보드 스크린샷을 크게 장식하지 않고, 카드 하단에 `전사 · 근거 · 상태 추적` 세 가지 미리보기만 둔다.
- 첫 화면은 스크롤 없이 완료되어야 한다.

### 전환 동작

- 기본 버튼 문구는 **`녹음으로 시작하기`**로 사용한다. 기본 REPLAY 시연도 사용자의 관점에서는 녹음 흐름을 시작하는 행동으로 설명한다.
- 필수 선택이 없으면 버튼을 비활성화하고, 무엇을 고르면 되는지 바로 알려준다.
- 클릭 후 선택 카드가 브리핑 카드로 바뀌며 `예적금 중도해지 · replay`처럼 선택 결과를 확인시킨다.
- 브리핑에서는 `필수 안내 N개`, `최근 규정 변경`, `모드`를 짧게 보여준 뒤 S1로 진입한다.
- 기본 경로는 `replay` 녹취 재생으로 두어 심사위원이 마이크 권한에서 막히지 않게 한다.
- `live`는 녹음 고지와 녹음·분석 중 표시를 먼저 안내한다.
- 이동 중에는 1회성 `브리핑 준비 중` 상태만 사용한다. 의미 없는 로딩 애니메이션을 넣지 않는다.

### 랜딩 문구

- Eyebrow: `실시간 금융 상담 컴플라이언스`
- 제목: `외우지 않아도, 빠뜨리지 않습니다`
- 설명: `규정과 상품설명서에서 뽑은 항목을 상담 중에 하나씩 확인하고, 설명했다는 근거를 남깁니다.`
- 폼 제목: `어떤 상담을 시작할까요?`
- 보조 문구: `상담 유형을 고르면 녹취·전사·근거 확인 흐름을 준비합니다.`
- 기본 CTA: `녹음으로 시작하기`
- 입력 오류: `상담 유형을 선택해 주세요`

## 7. 랜딩·기능·브랜드의 연결

랜딩에서 선택한 값은 대시보드의 첫 상태와 직접 연결되어야 한다.

| 랜딩 선택 | 대시보드에서 즉시 반영할 것 |
| --- | --- |
| 예적금 중도해지 | 중도해지 이자율·우대이자율 미적용·만기후이자율·대안 항목을 체크리스트에 표시 |
| 주택담보대출 | LTV·소액임차보증금·확정 전 안내·금리인하요구권·중도상환수수료 항목을 준비 |
| replay | `REPLAY` 배지, 녹취 재생 중 상태, 기본 시연 스크립트 |
| live | `LIVE` 배지, 녹음·분석 중 상태, 녹음 고지 |
| text | `TEXT` 배지, 전사 입력창, 수동 체크 경로 |

튜토리얼 대화창은 랜딩의 녹음 설정부터 대시보드의 녹음 레일·전사·판정·근거까지 실제 읽기 순서를 따라간다.

- 기본: `상담 유형을 고르면 바름이가 필요한 안내를 준비해요.`
- 예적금: `중도해지 이자율부터 차근차근 확인해 볼게요.`
- 주택담보대출: `확정 전인 금리와 한도를 먼저 구분해 볼게요.`

## 8. 정보 우선순위와 상태 표현

### 개입 우선순위

`위험 신호 > 금지 발언 > 숫자 오류 > 재진술 > 역질문 > 누락 넛지 > 용어 밀도`

한 번에 하나의 개입만 주목시킨다. 전문용어 밀도는 경보가 아니라 상태 정보로 낮게 표시한다.

### 상태 문구

라이브 화면에서는 은행원을 비난하지 않는 문구를 기본으로 한다.

- 사용: `설명서 기준 확인`
- 사용: `확인이 필요한 항목`
- 사용: `근거 원문 보기`
- 사용: `일부 요소가 아직 확인되지 않았습니다`
- 피하기: `잘못 말했습니다`
- 피하기: `위반자`, `감시 중`, `실패`

단, 종료 리포트는 증빙 문서이므로 법적·운영 상태인 `미고지`, `부분 고지`, `위반`, `위험 신호`를 정확하게 표시한다.

| 녹음·전사 흐름 | 상단 진행 레일, 현재 위치·재생 위치·녹음 상태를 한 줄로 표시 |

## 10. 시연 장면 기준

### 예적금 중도해지

- 숫자 오류: 은행원 `0.5%` vs 설명서 기준 `연 0.10%`
- 재진술: 고객이 “그것밖에 못 받아요?”라고 되묻는 장면
- 금지 발언: 만기 후 금리가 그대로 유지된다는 잘못된 안내
- 위험 신호: 해지금을 가족이 알려준 제3자 계좌로 보내 달라는 요청
- 라이브 상태: 고지 `1/5`, 부분 고지 `1`, 개입 필요 `2`를 먼저 보여주고 종료 리포트에서 최종 상태를 확정한다.

### 주택담보대출

- LTV와 소액임차보증금 공제를 조건부로 안내
- 내부 결재 전 금리 확정 발언을 금지 발언으로 표시
- 중도상환수수료 숫자 오류
- 근저당 설정 질문에 쉬운 말 재진술
- 금리인하요구권 미고지

## 12. 리서치 종합과 적용 근거

### 12.1 사례에서 반복해서 확인한 패턴

| --- | --- | --- |

## 13. 최종 랜딩 결정안

리서치를 반영한 최종 결정은 다음과 같다.

```text
브랜드 히어로                         상담 시작 카드
┌──────────────────────────────┐     ┌──────────────────────────────┐
│ 실시간 금융 상담 컴플라이언스 │     │ 어떤 상담을 시작할까요?       │
│                              │     │                              │
│ 외우지 않아도,                │     │ 녹음으로 시작하세요.          │
│ 빠뜨리지 않습니다             │     │ [ 녹음으로 시작하기 ]           │
│                              │     │                              │
│ 규정과 상품설명서에서 뽑은     │     │ 세션 설정은 필요할 때만        │
│ 항목을 녹음·전사 중 확인합니다. │     │ 펼쳐서 바꿉니다.               │
│             녹음 → 전사 → 판정 → 근거 │     │                              │
└──────────────────────────────┘     └──────────────────────────────┘
```

- 첫 화면에서 제품이 무엇을 하는지 설명하고, 같은 화면에서 녹취 재생 상담을 시작한다.
- 기본 화면의 첫 행동은 `녹음으로 시작하기` 하나로 둔다. 상담 유형·모드·고객 라벨은 접힌 `세션 설정`에서 필요할 때만 연다.
- `replay`를 기본값으로 하며, 심사위원이 마이크 권한이나 회원가입에 막히지 않게 한다.
- 시작 후 녹음·녹취 진행 레일과 실시간 전사가 바로 보이도록 하고, 개입·근거·체크리스트를 같은 S1 화면에서 확인한다.
- 랜딩은 마케팅 페이지가 아니라 첫 작업을 완료하는 업무 입구다.
- 튜토리얼 안에서만 바름이의 말풍선으로 기능을 안내하고, 위반·위험 상태에서는 사용하지 않는다.

## 14. 반응형 기준

화면을 단순 축소하지 않고, 폭이 줄어들수록 정보의 순서를 유지하면서 열 수를 줄인다.

- `320~680px`: 랜딩과 대시보드는 한 열로 쌓고, 상단 메뉴는 가로 스크롤 가능한 터치 내비게이션으로 전환한다. 제목은 한 글자만 고립되지 않도록 폭별 줄바꿈을 확인한다.
- `681~850px`: 대시보드 셸은 상단 네비게이션으로 바뀌고, 본문은 읽을 수 있는 2열을 유지한다. 랜딩은 브랜드 설명 아래 상담 시작 카드가 이어지는 흐름을 사용한다.
- `851~960px`: 사이드바는 유지하되 대시보드 본문을 한 열로 바꾸고, 보조 카드만 2열로 배치해 개입 카드가 좁아지지 않게 한다.
- `961px 이상`: 고정 사이드바와 `개입·전사 / 필수 안내·근거` 2열 구성을 사용한다.
- 모든 주요 카드와 그리드 자식은 `min-width: 0`을 적용하고, 가로 스크롤은 콘텐츠가 의도한 메뉴에만 허용한다.
- 튜토리얼은 각 폭에서 하이라이트와 대화창이 겹치지 않아야 하며, 바름이 이미지와 설명 텍스트가 대화창 안에 남아야 한다.
