# 최종 프론트 구현 및 실서버 검증 상태

검증일: 2026-09-05 · 로컬 작업 트리 · 이전 감사 이후 구현/재검증 결과

> 후속 프론트 작업으로 [동선·상세 단계 축소](USER_FLOW_SIMPLIFICATION.md)를 반영했다. 바로 실행·단일 상세창·리포트 직접 TRACE·새 상담 설정 유지의 실서버 검증을 통과했다. 아래 백엔드 보류 사항은 별개로 유지된다.

## 결론

**프론트의 확인된 연결·피드백 결함을 보완하고 실서버 검증을 수행했다. 서비스 전체 완료 판정은 보류한다.** 분리 발화 숫자 경보, REPLAY 종료 확정, PDF 처리 안정성의 서버 결함과 최근 규정 변경 제공 계약이 남아 있다.

수정 파일은 `front/` 안에 한정했다. 기존 작업을 보존했으며 팀원 백엔드 구현·규정 원문·발행 팩을 수정하지 않았다. 커밋/푸시/머지는 이번 작업에 포함되지 않는다. 검증용 상담만 생성·정상 종료했으며, 실제 규정 후보 승인이나 새 팩 발행은 실행하지 않았다.

기준은 `docs/기획/핵심기획안.md`, `back/contracts/`의 REST·WS·이벤트·규정 팩 계약과 실제 응답이다. 전체 대조 목록은 [수정 전 감사](FINAL_INTEGRATION_AUDIT_20260905.md)의 §5·§6에 보존했다. 이 문서가 최신 판정이다.

## 반영 내용

| 영역 | 실제 동작 및 피드백 |
| --- | --- |
| 상담 준비 | 실제 발행 팩·고객 유형·LIVE/TEXT 선택. 필수 안내/필요 서류는 서버 응답만 표시. 외부 STT·AI 처리 안내를 짧게 제공 |
| 녹음 | 버튼으로 실제 마이크 연결/중지. 연결 대기, 녹음 상태, 오류 표시. 중지는 상담 종료와 구분 |
| 상담 주요 버튼 | 네 개의 동등한 장식 카드 대신 녹음을 주 조작으로, 나머지는 간결한 참조 버튼으로 구성 |
| 필수 안내 | 실제 체크리스트로 이동, 선택 상태 및 대상 박스 pulse. 판정 상태·미충족 요소가 바뀌어도 강조 |
| 필요 서류 | 적용 팩의 서류 목록을 즉시 열기. 불필요한 WS 요청 없음. 빈 팩은 등록된 서류가 없다고 표시 |
| 상담 기준 | 적용 중인 팩 항목→필수 요소·승인된 쉬운 말·근거로 이동. 임의 기준 생성 없음 |
| 상담 대화/가이드 | 좌측 화자별 말풍선, 우측 가이드/필수 안내. 새 전사·새 개입 및 대기열 변경 시 관련 박스 강조. 위험 신호 우선순위 유지 |
| 쉬운 말 | 수동 요청 후 전용 모달에서 대기→실제 응답/오류→다시 요청. 필수 안내 탭이나 우선순위가 높은 경보 때문에 결과가 숨지 않음 |
| 수동 기록 | 고지/취소/제외/경보 확인 요청 후 중복 클릭 방지. 실제 서버 판정·영구 이벤트를 확인한 뒤 저장 완료 표시. 다른 경보 확인을 자신의 요청 성공으로 오인하지 않음 |
| 규정 질문·근거 | 실제 answer와 evidence 연결. 근거 없는 답변은 표시하지 않음. 보고서를 연 상담의 팩으로 정확한 출처 URL 연결 |
| 리포트 | `label`, `met`, 화자 등 메타데이터를 사용자 용어로 표시. 발화 원문·인용·숫자는 바꾸지 않음 |
| PDF | 실제 서버 PDF 요청/서명 확인. 읽기 쉬운 전체 리포트 인쇄·PDF 저장 화면과 서버 원본 다운로드를 함께 제공. 원본 실패/시간 초과 시 대체 출력임을 명시 |
| TRACE/REPLAY | 첫 발화 전 로딩, 실패/빈 기록 안내, 실제 저장 이벤트 재생. 기존 두 프리셋 음원과 발화 동기화 경로 유지 |
| 후보 검수 | 이름·필수 요소·승인할 쉬운 말 편집을 계약의 `edits`로 전달. 수정/원문 보기 반복 시 수정값 보존. 저장 대기·실패·재시도, 원문 불일치 승인 방지 |
| 업로드/발행 | 업로드 진행과 추출 완료/실패 표시. 발행은 완성된 승인 팩 JSON을 제출하는 실제 API 방식임을 명시. 자동 컴파일을 구현한 것처럼 표시하지 않음 |
| 조회 안정성 | 동일한 동시 GET만 공유. 완료 결과는 캐시하지 않으며 다시 조회 가능. 인증 변경/실패 재시도는 분리하고 쓰기 요청은 합치지 않음 |

디자인은 기존 청록·하늘색 브랜드를 유지하고 중복 강조를 줄였다. pulse는 짧은 테두리/안쪽 강조이며 레이아웃을 움직이지 않는다. `prefers-reduced-motion`이면 애니메이션 대신 정적인 강조만 잠시 표시한다. 큰 완료 패널이나 임의 기획 내용을 추가하지 않았다.

## 실행 검증

### 통과

- TypeScript 검사, 프로덕션 빌드 통과. 최신 빌드 디렉터리 `.next-final-feedback-202609051040`는 개발 서버와 분리했다.
- 계약 fixture: 판정 버전 역전·축 분리·경보 우선순위·서버 progress·근거·PCM16·관리자 인증·경보 확인 대응 검사 통과.
- `api-read-unit.cjs`: 동시 읽기 공유, 재시도, 인증 격리, 쓰기 중복 요청 미합치기 통과.
- 실제 로컬 TEXT 상담: 재진술/재요청, 고지/취소/제외, 근거 있는 질의 답변, 위험 경보 확인 저장, 리포트·DB 이벤트, 방금 저장한 상담의 TRACE 첫 발화 재생 통과.
  - 상담 `01M1RHT3CSPWHBAZ64WWJEHAD8`
  - TRACE `01M1RHTBNCYCC20THW8BZMJ546`
- 실제 음성 입력 파이프라인 검사: 테스트 음원을 가상 마이크로 전송하여 PCM 412프레임→전사 6건→판정 3건→경보 1건→DB 저장을 확인했다. 사람의 실제 마이크 품질이나 모든 화자 분리 정확도를 보증하는 검사는 아니다.
  - LIVE `01M1RGR8S7F840YXW7SCVH1TF4`
- REPLAY 예금/대출 음원과 서버 자막 시작·음소거·종료 UI 검사 통과. 이력에서 기존 음원 연결/다시 재생 검사 통과. **종료 뒤 이벤트 저장 결함은 별도 실패로 아래에 명시했다.**
- 관리자 REST 인증 및 잘못된 요청 거절 확인. 실제 인증/문서·후보 조회 정상. 승인 저장 UI는 격리된 응답으로 요청값/대기/실패/재시도를 검증했으며 실제 후보를 승인하지 않았다.
- 화면·모달 **100개 크기/상태 조합** 검사 통과: 상담/브리핑/서류/기준/쉬운 말/근거/리포트 70, 실제 후보 상세 10, 후보 편집·업로드 20. 1920×1080부터 320×568까지 검사한 범위에서 문서·내부 스크롤, 화면 밖 버튼, 패널 넘침·형제 요소 겹침을 발견하지 못했다. 임의의 모든 화면 크기에 대한 보증은 아니다.

### 증거와 재실행

`front/qa-output/`에 `final-feedback-qa.json`, `final-feedback-layout.json`, `final-live-feedback-qa.json`, `candidate-qa.json`, `final-admin-feedback-qa.json`, `voice-qa.json`, `replay-audio-qa.json`, `history-audio-qa.json`, `integration-findings.json` 및 화면 캡처를 저장했다. 토큰·키는 결과에 포함하지 않는다.

프론트 폴더에서 실행:

```text
npx tsc --noEmit
node scripts/contract-qa.cjs
node scripts/api-read-unit.cjs
node scripts/final-feedback-qa.cjs
node scripts/candidate-qa.cjs
node scripts/final-admin-feedback-qa.cjs
node scripts/final-live-feedback-qa.cjs
```

마지막 스크립트는 실제 로컬 상담을 생성·기록·종료한다. 격리 응답 테스트와 실제 저장 검사는 혼동하지 않는다.

로컬 실행은 기존대로 루트에서 `back/.venv/Scripts/python.exe front/scripts/local-backend.py`, 프론트에서 `npm run dev`를 사용한다. 문서 폴더 진단용 `--docs-dir` 옵션만 추가했으며 기본 경로는 원본 규정 문서 폴더다. 테스트용 PDF 복사본은 근본 해결이 아니므로 기본 실행에 사용하지 않는다.

## 서비스 전체 완료를 막는 항목

### 1. 분리 발화에서 숫자 경보 누락 — M2 백엔드

새 요청으로 재현했다. 같은 문장에 세금 맥락과 `14%`를 함께 입력하면 숫자 경보가 발생하지만 두 발화로 나누면 발생하지 않는다.

- 한 발화: `01M1RGTZ3PFWTKNDK1X6CE2XP6` — 경보 있음
- 분리 발화: `01M1RGV44YFBSWKREDRRQQD8VY` — 경보 없음
- 증거: `qa-output/integration-findings.json`

프론트는 수치를 고치거나 임의 경보를 만들지 않았다. 같은 문맥이 분리되어도 규정 근거를 연결한 실제 경보가 발생해야 통과다.

### 2. REPLAY 종료 뒤 전사/판정 저장 — M1·M2 백엔드

일부 TEXT/LIVE 검사는 종료 뒤 저장이 없었지만, 최신 두 REPLAY 검사의 DB 기록에는 종료 이벤트 뒤 두 건씩 남았다.

- DEP `01M1RH2JGAF2FAH9AZF4NYFBMT`: 종료 뒤 utterance 2건
- LOAN `01M1RH3SFNT2WF1QBJCJ2CJE4C`: 종료 뒤 verdict 1건 + utterance 1건

세션 종료 확정 전에 잔여 전사·판정 처리가 끝나야 한다. 화면에서 이벤트를 숨기거나 임의 대기시간을 추가하는 것으로 서버의 최종 리포트 일관성이 해결됐다고 간주하지 않는다.

### 3. PDF 동시 처리 안정성 — M1 백엔드

문서 목록 중복 조회 중 `PdfiumError: Data format error`가 발생했고, 별도 재현에서는 Windows Application 이벤트 1000에 `python.exe / pdfium.dll / 0x80000003` 오류가 남으며 서버가 종료됐다. 원본 7개 PDF는 각각 독립적으로 정상 열렸다. 복사 폴더에서도 프로세스 종료가 발생했으므로 원본 손상 또는 경로 문제로 단정할 수 없다.

프론트의 중복 GET을 합친 이후 동일 문서/후보 UI 검사는 통과했다. 다만 여러 브라우저나 직접 API 호출까지 보호하는 서버 수정은 아니다. PDFium은 서로 다른 문서라도 스레드에서 동시에 호출하면 안 된다고 명시한다. 관측된 중복 요청과 네이티브 오류를 고려할 때 동시 처리 보호 누락이 유력하지만, **담당 구현의 lock/프로세스 분리 확인 전까지 원인을 확정하거나 해결 완료로 판정하지 않는다.** [pypdfium2 공식 제약](https://pypdfium2.readthedocs.io/en/stable/python_api.html#incompatibility-with-threading)

서버 PDF의 최초 생성이 프론트 제한 시간보다 늦은 실행도 있었다. 이때 전체 JSON 기반 인쇄 대체 화면을 제공한다. 서버 원본 PDF의 타임라인에는 영문 내부값이 남아 있으므로 원본 파일을 사용자용 한글 출력과 구분했다.

### 4. 최근 규정 변경 브리핑 — 기획·계약·백엔드

기획 §7.1·§7.2에는 구현 대상으로 적혀 있으나 현재 REST/WS·브리핑에는 변경 피드가 없다. 감시 스크립트의 존재만으로 화면 연결 완료라고 할 수 없다. 변경 내역·출처·적용 팩을 제공하는 계약이 필요하다. 브리핑 생성 시각을 규정 변경 시각으로 꾸미지 않았다.

### 검증/범위 유보

- 신규 문서 업로드→실제 사람 승인→자동 컴파일→새 발행 팩→상담 적용의 연속 쓰기 시나리오는 완료로 승인하지 않았다. 현재 공개 API에 자동 컴파일 접점은 없고, 프론트 발행은 완성 팩 JSON을 받는다. 별도 테스트 문서·팩 버전과 담당자 검수로 검증해야 한다.
- LOAN 필요 서류는 검증된 원천/팩 필드가 없어 비어 있다. 기획 §9 보정에서도 원천 확보 뒤로 미뤘으므로 프론트가 추정해 채우지 않는다.
- 배포 사이트와 이 로컬 작업 트리의 동일성·운영 보안·실제 두 사람의 마이크 품질은 이번 완료 범위가 아니다.

기존의 “다른 팀원 코드는 고치지 말 것” 범위 때문에 위 서버 구현과 계약은 변경하지 않았다. 백엔드 결함 수정 허용 또는 담당자 수정 후 회귀 통과가 있어야 서비스 전체를 완료로 판정할 수 있다.
