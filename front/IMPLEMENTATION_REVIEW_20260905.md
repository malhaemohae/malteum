## 표시하지 않는 내용과 알려진 차이

- 임의 경고·성공 수치·키워드 기반 프론트 판정·서버 실패를 숨기는 로컬 시연을 제거한다. API 실패 시 오류와 재시도만 제공한다.
- 기획에는 최근 규정 변경이 있지만 현재 브리핑 계약에는 변경 내역 필드가 없다. 생성 시각을 최근 규정 변경으로 둔갑시키지 않고 미표시한다.
- 가계 신용대출 팩을 주택담보대출이라고 바꾸어 표시하지 않는다. 실제 발행 팩 명칭을 사용한다(기획 §9의 발행 팩 차이와 일치).
- LIVE 중 텍스트 폴백은 입력 UI만 바꾼다. 서버 세션 모드·이력은 LIVE 그대로이며 녹음을 다시 시작할 수 있다.
- 고객 유형은 계약대로 전송하지만 현재 백엔드 브리핑 문안이 유형별로 달라진다고 보장하지 않는다.
- 영구 저장·STT·LLM·문서 추출·관리자 인증은 서버 환경의 책임이다. 프론트 성공 표시로 대체하지 않는다.
- 규정 개정 감시 시스템은 기획에 있으나 현재 공개 REST 계약에 대시보드용 조회 경로가 없다. 새 API를 추측해 붙이지 않는다.

## 고정 화면 레이아웃

- 랜딩과 분리된 `.wb-service` 테마, `100dvh`, 흰색 사이드바와 본문 내부 패딩으로 작업 영역을 구분한다.
- 상담·리포트·이력·팩·문서와 상세창 모두 스크롤 대신 영역 높이 기반 페이지 전환.
- 긴 제목·발화는 요약 행에서 선택하면 전체 원문 페이지로 확인한다. 원문 내용을 잘라 버리지 않는다.
- 데스크톱 상담은 상단에 녹음/입력·필수 안내·필요 서류·기준 확인 액션을 놓고 아래에 넓은 대화 영역을 둔다. 오른쪽은 제목 띠가 있는 하나의 상담 가이드로 묶어 현재 개입·규정 질문과 필수 안내 목록을 전환한다. 새 업무나 가짜 수치는 추가하지 않는다.
- 고객은 왼쪽, 상담원은 오른쪽, 시스템은 가운데로 구분하며 서버의 화자 값을 재판정하지 않는다. 전체/고객/상담원 필터는 화면에 보이는 전사만 선택하며 저장된 전사나 서버 판정을 바꾸지 않는다.
- 전사는 실제 말풍선 높이를 측정해 최신 발화부터 화면을 채운다. 이전 페이지를 읽는 동안에는 새 발화가 와도 보고 있는 기록을 유지하고 `최신 발화`로 돌아간다. 긴 발화는 말풍선을 선택해 전체 원문을 읽는다.
- 폭 800px 이하에서는 상담 대화·현재 안내·필수 안내 중 한 영역을 선택한다. 녹음/입력·필요 서류·기준 확인 버튼은 위에 유지한다. 새 안내 수는 탭에 표시하며 사용자가 보고 있는 탭을 임의로 바꾸지 않는다. 넓고 낮은 데스크톱은 좌우 배치를 유지한다.
- 상단 헤더에 별도 패딩을 확보하고 리포트의 팩 버전은 오른쪽 도구 영역으로 옮겼다. 사이드바 로고의 흰색 변환 필터를 제거하고 원본 색상·비율을 유지한다.
- 근거 bbox는 PDF의 아래쪽 원점을 이미지의 위쪽 원점으로 변환한다: `top = (pageHeight - y2) / pageHeight`.
- 리포트의 상세 설명·출처·유의사항은 `요약·출처`에서 확인하고 인쇄에도 전부 포함한다.

### 상담 좌우 배치 후 재검증 (이전 배치 기록)

- `node scripts/consultation-layout-qa.cjs`: 실제 서버에 하나은행 대본 10개 발화와 추가 확인 발화 1개를 TEXT로 전송. 고객·상담원 표시, 실제 경보, 좌우 정렬, 원문 모달, 이전/최신 페이지, 10개 화면 크기의 3개 상담 탭, 리포트 버전·상단 간격 검사 **62건 통과**.
- `node scripts/workspace-qa.cjs`: 실제 API/WS 기반 기존 기능·레이아웃 **235건 통과**, 페이지 오류·스크롤·영역 겹침 0건. 마이크 패킷 송신·재시작, 수동 보완·근거·질문·리포트·TRACE 포함. 이 검사는 두 사람의 실제 음성 화자 분리 정확도를 평가한 결과가 아니다.
- TypeScript, 프론트 계약/PCM 단위 검사, `.next-verify` 프로덕션 빌드 통과. 앞서 기록한 백엔드 숫자/종료 처리 두 건은 이번 UI 변경으로 수정하지 않았다.

```powershell
node scripts/contract-qa.cjs
node scripts/consultation-layout-qa.cjs
$env:MALTEUM_NEXT_DIST_DIR='.next-verify'; npm run build
# 정상 PostgreSQL 서버와 front가 있을 때
```

`QA_FIXTURE_CATALOG`는 테스트 브라우저의 팩/문서 목록·브리핑/추출 GET만 계약 fixture와 저장소 추출 원문으로 공급한다. 제품 코드에는 fixture 폴백을 넣지 않는다. 실제 backend의 메모리 이벤트 저장소에서 세션 생성·WebSocket·판정·수동 보완·근거·종료 리포트·TRACE를 별도로 검사한다. 이 결과는 PostgreSQL 영구 저장이나 실제 음성 STT 성공을 뜻하지 않는다.

2026-09-05 Docker 재기동 후 PostgreSQL 검증을 완료했다. Windows 예약 범위에 포함된 5432 대신 `127.0.0.1:15432`로 연결하며 기존 `malteum_pgdata` 볼륨을 유지한다. 마이그레이션 `0002`, 공식 팩 2개·임베딩 58개를 적재했고 DB와 백엔드 재시작 전후 세션·이벤트·리포트·팩의 동일성을 확인했다. 초기 소켓 복구 과정에서는 소켓·DB 볼륨을 삭제하지 않았다.

사용자가 제공한 개인키로 팀 `.env.age`를 복호화해 Git 제외 경로 `front/.env.backend.local`에 저장했다. 원래 개인키와 암호문은 수정하지 않았다. 로컬 실행·키 처리·검증 명령의 정본은 [LOCAL_RUN.md](LOCAL_RUN.md)다. 실제 OpenAI 전사, OpenRouter L3·화자 역할 판단, L2 임베딩과 Docker 화자 분리 호출을 확인했다. 통합 검수의 남은 결함은 위의 별도 문서가 정본이다.

검증 결과는 `front/qa-output/workspace-qa.json`에 기록되며 Git에는 포함하지 않는다.
