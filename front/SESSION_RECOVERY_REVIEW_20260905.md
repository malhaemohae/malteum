# 미종료 상담 이력 복구

상태: 다른 팀원 코드를 수정하지 않고 기존 서버의 연결 순서에 맞춰 프론트에서 복구하고 로컬 검증을 완료했다. 운영 배포 상태는 별도로 확인한다.

## 화면 변경

- `running`도 서버 리포트를 조회한다. 제목은 중간 리포트이며 최종 결과가 아님을 표시하고 PDF 최종 출력은 제공하지 않는다.
- 이력의 미종료 상담에는 중간 리포트와 상담 열기를 제공한다. TRACE가 종료 이후 가능하다는 이유를 같은 행에 표시한다.
- 상담 열기는 동일 ID의 서버 요약·기존 발화를 불러오고 `hello(session_id)` → `ready` → `resume` 순서로 연결한다. 마이크는 자동으로 켜지지 않는다. 다시 수신한 `ready`에서 `resume`을 반복하지 않는다.
- 원본이 아닌 TRACE 이력과 발화·판정·안내·경보가 하나도 없는 기록은 새 TRACE 세션을 만들기 전에 차단·안내한다.
- 종료 응답이 유실되거나 연결이 끊겼을 때 REST의 상태로 종료 여부를 확인한다. 프론트가 종료 상태를 임의로 가정하지 않는다.
- 저장 발화의 원문과 서버 파생 항목 상태만 복원한다. REST 이벤트 순번을 WS 순번으로 사용하거나 프론트에서 진행률을 합산하지 않는다.

## 서버 변경 없이 사용한 연결 경로

`ws://127.0.0.1:8000/ws`에 새 연결의 첫 메시지로 계약상 `resume`을 보내면 다음 오류가 반환된다.

```json
{"t":"error","code":"invalid_message","message":"hello 가 먼저입니다.","retryable":false,"seq":0}
```

계약의 `hello.session_id`는 기존 세션에 이어 붙이는 용도다. 따라서 먼저 같은 ID로 `hello`를 보내고 `ready` 이후에 한 번만 `resume`을 보낸다. 새 세션 생성 POST는 하지 않는다. 이전에 서버 수정이 필수라고 판단한 것은 철회한다.

기존 서버는 재접속의 `hello`에도 같은 ID의 `session_started` 이벤트를 추가한다. 이 현상은 새 세션 레코드가 생기거나 최초 시작 시각이 변경되는 것과는 다르다. 추가 REPLAY 검증에서 같은 ID·같은 started_at 유지, 재접속 뒤 30초 동안 첫 발화 중복 없음, 이후 발화 수신과 실제 종료를 확인했다. 기존 이벤트는 삭제하거나 UI에서 임의로 고쳐 저장하지 않는다. 감사 로그의 추가 시작 이벤트는 기존 서버 동작으로 남아 있으며 이를 해결했다고 주장하지 않는다.

이 실험은 로컬 합성 세션에만 실행했다. 운영 서버의 기존 사용자 상담을 임의로 종료하거나 수정하지 않았다.

## 완료 범위와 한계

1. 이력에서 중간 리포트 → 상담 열기 → 종료 → 종료 리포트 → 원본 TRACE를 실제 로컬 REST/WS로 검증했다.
2. 브라우저 새로고침 후에도 같은 ID·시작 시각·기존 발화·수동 판정을 유지한다. 서버의 기존 이벤트 원문 불변과 종료 이벤트 1건을 확인한다.
3. 다른 상담이 열려 있을 때 새 TRACE를 만드는 동작은 차단하고 현재 상담으로 돌아가는 경로를 안내한다.
4. 무발화 LIVE 상담을 마이크 자동 시작 없이 다시 열어 종료할 수 있다.
5. 저장 발화가 없는 TRACE는 생성하지 않는다. 이미 만들어진 TRACE 이력을 재차 TRACE하는 동작도 막는다.
6. 서버 프로세스 재시작 이후의 WS 로그 영속성, TRACE 자동 완료·원본 연결 저장 문제까지 고친 것은 아니다. 기존 TRACE 진단 문서의 서버 항목은 별개다.

## 검사 명령

통과: TypeScript, 기존 계약/PCM·랜딩 검사, 복구 유틸 단위 검사, 실제 로컬 API/WS의 복구 전체 흐름, 리포트·이력·대시보드·빈 TRACE의 320~1920px 40개 화면 조건. 작은 리포트 화면은 항목 탭을 동일한 옵션의 선택 상자로 표시해 세로 공간을 확보한다.

```powershell
cd front
node scripts/session-recovery-unit.cjs
node scripts/contract-qa.cjs
node scripts/landing-qa.cjs
node node_modules/typescript/bin/tsc --noEmit
$env:QA_REPORT_ONLY = '1'
node scripts/session-recovery-qa.cjs
Remove-Item Env:QA_REPORT_ONLY
# 기존 서버 그대로 전체 실제 연결 검증:
node scripts/session-recovery-qa.cjs
```

`QA_REPORT_ONLY=1`은 중간 리포트·이력·빈 TRACE와 30개 화면 조건만 검증한다. 기본 전체 검사는 새로고침 이후 같은 ID 재연결, 새 세션 생성 요청 없음, 최초 시작 시각 유지, 기존 이벤트 불변, 전사 중복 없음, 종료 기록 1건을 요구한다. 연결별 시작 로그 추가는 서버의 실제 동작대로 명시적으로 검증하며 삭제·은폐하지 않는다. 검사는 localhost/127.0.0.1로 제한하고 자신이 만든 합성 세션만 종료한다.
