# 엔진 수정 및 Qwen3-8B 의미 귀속 검증

## 결론

숫자 관련 두 문제는 각각 수정 PR과 회귀 테스트가 있습니다. 두 수정을 합친 A 단일 음성 E2E도 통과했습니다. 세 번째 의미 귀속 문제는 미해결입니다. 시나리오별 퓨샷과 후처리 차단 실험을 채택하지 않았으며, 세 번째 해결 PR은 만들지 않았습니다.

| 문제 | 처리 결과 |
| --- | --- |
| 복합 금리 문장에서 가산금리 오류 경보 누락 | [복합 금리 귀속 수정 PR](https://github.com/malhaemohae/malteum/pull/47)을 작성했습니다. 신규 9개 테스트가 통과했습니다. |
| 위법계약해지 기간의 기산점 혼동 및 잘못된 기준값 표시 | [기산점별 숫자 비교 수정 PR](https://github.com/malhaemohae/malteum/pull/48)을 작성했습니다. 신규 13개 테스트가 통과했습니다. |
| 다른 주제의 발화를 기한이익상실 설명으로 인정 | 일반화 검증에 실패했습니다. 기대값을 유지한 실제 모델 재현 테스트만 남겼습니다. |

두 PR은 `dev` 대상이며 CI가 통과했습니다. 병합하지 않았습니다. 프런트와 계약 스키마는 수정하지 않았습니다.

## 고정 조건

- LLM은 OpenRouter `qwen/qwen3-8b`, temperature 0, reasoning off로 고정했습니다. 교정·답변 생성 모델은 사용하지 않았습니다.
- 집중 검사는 개발 문장 6개와 별도 검증 문장 12개를 각각 3회 호출합니다. 캐시를 사용하지 않으며, 실제 토큰 사용량이 없는 호출은 성공으로 인정하지 않습니다.
- 상태뿐 아니라 `missing_elements`도 일치해야 통과합니다. 모델의 실패에 맞춰 기대값을 바꾸거나 `xfail`로 처리하지 않았습니다.
- 이 검사는 L3 후보와 사전 상태를 명시한 집중 검사입니다. L1/L2 후보 선택이나 ASR을 포함한 전체 엔진 정확도로 환산하지 않습니다.
- 별도 검증 문장 파일의 SHA-256은 `fb5ff4e2ff91b8ef10e0405b0d76d09bb5079fdba48424457d01b77f1e718a58`입니다. 최초 실행 후 파일을 변경하지 않았습니다. 이제 결과를 확인했으므로 이후에는 미사용 평가셋이 아니라 고정 회귀셋으로 취급합니다.

## 퓨샷 없는 재검증

| 구성 | 개발 문장 18회 | 별도 검증 36회 | 합계 |
| --- | ---: | ---: | ---: |
| L1/L2 주제 근거로 L3 결과를 차단하는 실험 | 15/18 | 15/36 | 30/54 |
| 실험을 원복한 현재 구현 | 9/18 | 15/36 | 24/54 |

차단 실험은 기존 연체금리 문장과 가까운 표현의 오탐을 막았지만, 별도 검증에서는 개선이 없었습니다. 별도 검증의 동일한 모델 응답을 차단 적용 전후로 비교했을 때도 15/36으로 같았습니다. 새로 발생한 회귀가 없다는 사실만으로 문제 해결이라고 판단하지 않았습니다.

현재 구현에서 다음 오류는 각각 3회 모두 재현됐습니다.

- 기존 연체금리 문장과 개발용 유사 표현을 기한이익상실 설명으로 인정합니다.
- 연체 시 추가 이자를 설명하는 새로운 표현과 정상적인 만기 상환 설명도 기한이익상실 설명으로 인정합니다.
- 기한이익상실의 원인과 결과를 모두 풀어 말해도 일부 설명이 빠졌다고 판단합니다.
- 앞선 은행원 설명에 이어 불이익을 설명해도 항목을 완료 상태로 갱신하지 않습니다.
- 세금을 공제한다는 설명을 중도해지 불이익으로 인정합니다.
- 중도해지 시 이자가 줄어든다는 설명만으로 적용 이율까지 설명했다고 인정합니다.
- 두 주제를 함께 설명한 발화에서 명시된 기한이익상실 사유를 누락으로 판단합니다.

실패 원인은 단순한 응답 형식 오류가 아닙니다. L2의 유사도는 판정 후보를 찾는 신호인데, L3가 이를 실제 설명의 근거처럼 해석합니다. 인용 문구를 추가로 요구해도 문구가 실제 발화에 있다는 사실만 확인할 수 있고, 그 문구가 해당 요건을 뒷받침하는지는 보장하지 못했습니다. 일반 키워드 차단 역시 표현이 달라지면 같은 오탐을 놓쳤습니다.

따라서 현재 실험을 근본 해결로 채택하지 않습니다. 다음 수정안에서는 주제·조건의 구분과 요건별 충족 판정을 분리하는 구조를 검증해야 합니다. 추가 호출이 필요하다면 Qwen3-8B 고정 조건과 실제 3초 예산도 함께 확인해야 합니다. 이 구조의 구현 및 검증은 아직 완료하지 않았습니다.

시나리오와 가까운 퓨샷을 넣었을 때의 과거 22/22 통과 결과는 일반화 성능 근거에서 제외했습니다. 해당 퓨샷 및 이번 차단 실험은 현재 엔진 코드에 남아 있지 않습니다.

## 숫자 수정의 A 단일 음성 E2E

로컬 통합 브랜치 `feat/engine-regression-qa`에는 두 숫자 수정만 포함했습니다. Qwen3-ASR-1.7B, Sortformer, multilingual-e5-small과 위 OpenRouter 모델을 사용했습니다. 새 서버와 빈 캐시로 A만 1회 재생했습니다.

- 최종 요약은 1/1 일치했고, 항목 상태는 8/8 일치했습니다.
- 경보는 TP 3, FP 0, FN 0이었습니다.
- 화자는 27/27 일치했고, 원본 발화는 16/16 포함됐습니다.
- 이벤트 식별자·순서, 종료 후 이벤트 없음, 보고서 일치와 PDF 응답을 확인했습니다.
- L3 처리 결과는 7회 수집했지만, 그중 적어도 1회는 실제 3초 제한에 걸려 잠정 판정을 유지했습니다. 정확도 통과가 지연시간 예산 통과를 뜻하지 않습니다.

산출물은 `/tmp/malteum-numeric-fixes-20260907/`에 있습니다. 세 번째 수정까지 포함한 E2E 결과는 아닙니다. B~D 전체 음성 재검증과 프런트 QA는 수행하지 않았습니다.

## 재현 및 산출물

저장소 루트에서 외부 모델을 끈 `make test`는 원복 후 **601 passed, 60 skipped**였습니다. 60개 생략에는 새 집중 검사 54개가 포함됩니다. 오프라인 통과를 실제 모델 정확도 통과로 해석하지 않습니다.

```sh
APP_LLM_MODEL='' APP_ANSWER_LLM_MODEL='' APP_EMBEDDING_MODEL='' make test
```

`back/`에서 아래 명령으로 고정 검사를 실행합니다. OpenRouter 키가 필요하며 현재 구현에서는 **24 passed, 30 failed**로 종료 코드 1을 반환합니다. API 호출 비용이 발생합니다.

```sh
MALTEUM_LIVE_REGRESSION=1 uv run --no-sync pytest \
  tests/engine/test_live_scope_regression.py \
  --junitxml=/tmp/malteum-scope.xml \
  -o junit_logging=all -o junit_log_passing_tests=true
```

실제 원복 후 실행 기록은 `/tmp/malteum-scope-restored.xml`, 차단 실험 기록은 `/tmp/malteum-scope-final.xml`에 있습니다. 원복한 실험 변경은 `/tmp/malteum-rejected-scope-guard.diff`와 `/tmp/malteum-rejected-scope-test.py`에 별도로 보존했습니다. `/tmp` 산출물은 장기 보관을 보장하지 않습니다.
