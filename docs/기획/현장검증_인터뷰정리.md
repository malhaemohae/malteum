## 1. 출처와 한계

| | 1차 | 2차 |
| --- | --- | --- |
| 응답자 | 새마을금고 재직자 | **동일 인물** |
| 경력 | 입사 2년차 | 여신 부서 4개월, 그 전 수신 담당 |
| 형식 | 통화 약 1시간, 질문지 8항목 | 통화, 업무 프로세스 중심 |
| 본인이 밝힌 한계 | "요즘 대출팀에 있어가지고 수신 업무를 잘 모르긴 해" | "대출 들어간 지 4개월밖에 안 돼서 자세하게 알지는 못해", 사업자·법인 대출 미경험 |

**표본은 1명이다.** 새마을금고 한 지점, 경력 2년. 두 인터뷰가 같은 사람이므로 교차 검증이 아니라 같은 관점의 심화다. 다음 두 가지를 구분해서 쓰지 않으면 기획서의 신뢰도가 무너진다.

- 규제·법령에서 오는 것(망 분리, 고액 현금 인출 절차, 조세특례): 지점이 달라도 같다. 일반화 가능
- 관행에서 오는 것(예금자보호 한도 설명 생략, 단골 고객의 서류 간소화, 지점별 주담대 취급 기준): 그 지점의 사정이다. **일반화 금지**

응답자 본인도 1차에서 "은행들마다 약간씩 내부 규정들이 조금 다를 거라서... 우리 같은 경우에는 주택담보대출 내부 규정이 바뀌어가지고 우리 회원이 아닌 사람들은 지금 주담대를 다 거절하고 있거든. 근데 이제 다른 데들은 안 그러니까"라고 말했다. 이 문장이 일반화 금지선을 그어 준다.

## 2. 확정 사항 (우리 팀 결정)

### 2.1 이번에 새로 닫은 것

| # | 결정 | 근거 |
| --- | --- | --- |
| D1 | **배치는 내부망 기준으로만 설계한다** `[결정]` | 외부망·클라우드 GPU 서버·태블릿 연결 형상은 도입 은행이 자기 인프라 사정에 맞춰 정할 일이므로 우리 설계 범위 밖 |
| D2 | **제품 배치(내부망)와 심사 시연(공개 URL)은 다른 층으로 서술한다** `[결정]` | 대회 심사는 URL 접속 의무가 있음. 두 층을 섞어 쓰면 "인터넷이 안 되는데 URL 은 어떻게 접속하나"라는 모순으로 읽힘 |
| D3 | 상담 유형은 예금 신규 + 신용대출 2종을 유지한다 `[결정]` | 기획안 18장 기존 확정. 축소·전환 없음. 다만 5.2 의 주담대 논점 참조 |

**D1 의 논리적 귀결을 기획서에 반드시 적을 것.** 은행 내부망에는 인터넷이 없으므로, 내부망 배치를 전제하면 STT(Speech To Text: 음성을 글자로 바꾸는 기술)와 LLM(Large Language Model: 대규모 언어 모델)의 외부 API 호출이 불가능하다. 즉 **온프렘(on-premise: 외부 클라우드가 아니라 도입 기관 자체 전산실에 설치) 서빙이 기본값**이 된다. 기획안 11.3 은 지금 STT·LLM 을 외부 서비스로 적고 "어댑터 뒤에 두었으니 교체 가능"이라고만 서술하는데, D1 이후로는 **교체가 선택지가 아니라 전제**다. 서술 강도를 올려야 한다.

### 2.2 기존 확정 중 이번 인터뷰로 뒷받침된 것

| 기존 확정 | 뒷받침 |
| --- | --- |
| 1차 사용자는 경력 3년 미만 창구 직원 (3장) | `[I1]` "신규 직원들한테는 이게 도움이 엄청 많이 될 거 아니야" · `[I2]` "포커스는 나같은 신입 직원들한테 하는 게 좋긴 하니까 교육 자료로 써도 되는 거고" |
| 화면은 고객에게 보이지 않음 (8.2) | `[I1]` "안 보이는 게 맞는 것 같아요. 이게 은행을 돕는 거라서" |
| 상담 유형은 팩 추가로 확장 (6장) | `[I2]` 여신 유형이 주담대·땅담보·건물담보·사업자·법인으로 갈라짐. 코드가 아니라 데이터로 늘어나야 감당되는 구조임이 확인됨 |
| STT 품질 리스크 (16장 리스크 1) | `[I1]` "네이버에서 나온 클로바노트 쓰고 하거든? 거의 한 97%" 현업이 이미 실용 수준으로 체감 |

### 3.2 실제 아픈 곳

**중도해지가 감사 지적 1순위다.** `[I1]`

> "중도해지... 이번에 감사 나와가지고 지적 받았거든. 이게 좀 어려워. 중도해지 이자율이랑 이런 게"

중도해지가 수신 영역이라는 점은 2차에서 재확인되었다 `[I2]`. 반면 우리가 시연에서 누락 항목으로 심어 둔 두 가지는 현업 중요도가 낮다.

| 항목 | 현업 평가 | 라벨 |
| --- | --- | --- |
| 예금자보호 한도 | 포스터에 붙어 있고 통장에도 적혀 있음. 물어보는 사람에게만 설명. "굳이 빼도 될 것 같고" | `[I1]` |
| 만기후이자율 | 만기 뒤 이율이 입출금 통장 수준(0.1% 대)이라 실익이 작음. 상품마다 다름 | `[I1]` |

법적으로 두 항목이 면제된다는 뜻이 아니다. 응답자는 "이거는 법적으로 내가 고지해야 될 필요는 없긴 해"라고 말했으나 이는 개인 판단이며 `[검증]` 대상이다. **현업 체감 우선순위**로만 쓸 것.

### 3.3 대리인 내방

| 필요 서류 | 가족관계증명서 · 위임장 · 대리인 신분증 · 예금주 신분증 · 예금주 본인과의 통화 | `[I2]` |

## 4. 현장 사실: 여신 (대출)

### 4.1 유형 구분

```
대출
├─ 신용대출        신용도 기반. CB 등급 + CSS 등급 병용
└─ 담보대출
   ├─ 주택담보대출  가장 흔함. 우리 시연 후보로 거론됨
   ├─ 땅 담보       논·밭. 농촌 지점 특성
   ├─ 건물 담보
   └─ 사업자·법인   중소·영세기업. 협조융자 방식 존재
```

| 용어 | 뜻 | 라벨 |
| --- | --- | --- |
| CB 등급 | Credit Bureau(신용조회회사)가 매기는 개인신용평점 | `[I2]` + 표준 용어 |
| CSS 등급 | Credit Scoring System(자체 신용평가 모형). 새마을금고 자체 산출 | `[I2]` + 표준 용어 |
| 협조융자 | 한 금융기관이 감당하기 어려운 규모를 여러 기관이 나눠 취급. 주도하는 곳을 주간금고라 부름 | `[I2]` |

### 4.2 주택담보대출 절차 `[I2]`

| 순서 | 단계 | 비고 |
| --- | --- | --- |
| 1 | 고객이 금액·금리를 문의 | |
| 2 | 주소 확인 후 온라인 등기소에서 등기부등본 열람 | **외부망 필요.** 대출 담당자가 PC 2대를 쓰는 이유 |
| 3 | 감정: LTV(Loan To Value: 담보인정비율) 70% 적용 후 소액임차보증금 공제 | 인터뷰 진술 2,500만원. `[검증]` 지역·시점별로 다름 |
| 4 | 주택 소유 건수 · 소득 · 신용등급 조회 | |
| 5 | 대출 가능 금액과 예상 금리 안내. 확정 아님을 함께 고지 | |
| 6 | 고객 동의 후 내부 결재로 금리 확정 | |
| 7 | 상환 방식 · 이자 납입일 협의 | |
| 8 | 등기소에서 근저당 설정. 건물이 있으면 지상권 설정 병행 | |
| 9 | 서류 결재 완료 후 대출 실행 | |

5단계의 성격을 눈여겨볼 것. 확정되지 않은 금액과 금리를 안내하는 자리이므로, 우리 금지 발언 축(단정적 판단, 불확실한 사항의 확실 표시)이 정확히 작동해야 하는 지점이다 `[추론]`.

### 4.3 실제 아픈 곳

**신입이 자필 서명을 빠뜨린다.** `[I2]`

> "나 같은 존나 초보자한테는 내가 자필 서명을... 깜빡하고 못 적는 부분들이 많거든. 그래서 이제 못 받는 부분이 있으면 안 넘어간다든지"

1차의 "서류가 존나 많은데 요즘 내가 하나씩 계속 빠트리거든" `[I1]` 과 같은 축이며 2차에서 대상이 **서명 누락**으로 좁혀졌다. 응답자가 체크리스트를 어디에 쓰겠냐는 질문에 스스로 꺼낸 유일한 용처다.

**이 축은 음성이 필요 없다.** 서류·서명 체크는 상담 발화가 아니라 절차 상태를 본다. 6.2 의 녹음 리스크 대응에서 이 성질이 핵심 역할을 한다 `[추론]`.

### 4.4 규정 변경

여신은 수신보다 규정 변경이 잦다 `[I2]`. 1차에서 전달 경로가 확인되었다 `[I1]`.

```
금융위원회·금융감독원·행정안전부
  → 새마을금고중앙회 (문서 하달)
    → 지점 게시판 · 법규집 (변경 다음 날 아침 게시, 개정일자 표기)
```

- 은행 내부 법규집과 예금·대출 약관 원문은 **비공개** `[I1]`
- 정부 규제 원문(금융위원회 보도자료 등)은 공개 `[I1]`
- 즉 우리 regwatch(규정 개정 감시)가 볼 수 있는 것은 공개 원천까지이고, 도입 시에는 은행 내부 게시판 연동이 별도로 필요하다 `[추론]`

## 5. 제도·절차 사실

### 5.1 고액 현금 인출 `[I1]`

| 항목 | 내용 |

| 현장 마찰 | "문진표 받으라고 그러면 손님들이 화를 낸다. 왜 내 돈 내가 빼는데" |

### 5.5 서식과 속도 `[I1]`

- ESG(Environmental Social Governance: 환경·사회·지배구조) 경영 기조로 종이를 줄이고 전자서식 전환 중
- 다만 **피크타임에는 종이가 더 빠름.** 이유는 병렬 작업이다. "형광펜 그어놓고 손님이 사인하는 동안에 내가 설명해버리면 되니까." 전자서식은 직원이 확인 클릭을 계속 눌러야 함

이 사실이 우리 설계에 주는 제약은 6.1 의 P7 항목에 정리했다.

### 5.6 도입 저항 지점 `[I1]`

- 현장 직원은 저항이 크지 않을 것으로 응답자가 판단
- **결정권은 지역본부.** "이 새끼들이 좋다고 생각해야 우리가 쓸 수 있는 건데"
- 태블릿 등 단말 구매 부담은 낮게 평가. "지점에서 그런 직원들한테 태블릿 몇 대 사주는 건 1도 아닐 것 같은데"

### 5.7 본부 상담 창구의 한계 `[I1]`

본부에 업무 문의용 상담 인력이 있으나 답을 못 받는 경우가 있다. 응답자가 인터뷰 전체에서 **유일하게 먼저 요청한 기능**이 규정 질의 도구였다.

> "챗봇 형태로 문서들 같은 거 정보들 같은 거 끌어와서 이렇게 할 수 있는 건가? 그게 나도 존나 필요해. 존나 있었으면 좋겠어."

### 6.2 녹음 리스크 대응 (R8 의 세부)

2차 인터뷰의 부정적 신호는 감추지 말고 기획서에 리스크로 명시할 것. 은폐하면 심사에서 같은 질문이 나왔을 때 답이 없다.

**대응 논리는 이미 우리 설계 안에 있다.** 두 가지다.

| 방어선 | 근거 | 상태 |
| --- | --- | --- |
| 실행 모드 `text` | 기획안 11.4. 타이핑 입력으로 동일 판정 경로를 탐. STT 없이 동작 | 이미 확정 |
| ⑪ 수동 체크리스트 · ⑩ 텍스트 질의 · ⑥-A 쉬운 말 사전 | 기획안 7.1 의 3층 폴백. STT 없이 동작한다고 이미 명시 | 이미 확정 |

여기에 4.3 의 **서류·서명 누락 방지 축**을 더하면 음성 없이도 성립하는 기능군이 하나 더 생긴다. 서명 체크는 발화가 아니라 절차 상태를 보기 때문이다.

기획서에 넣을 서술 방향은 이렇다. 녹음이 허용되지 않는 기관에서는 텍스트·수동 모드로 도입하고, 허용되는 기관에서는 음성으로 자동화 수준을 올린다. **음성은 성능 축이지 존재 조건이 아니다.** 이렇게 쓰면 2차 인터뷰의 부정적 신호가 제품을 무너뜨리지 못한다.

단 정직하게 적을 것. 음성이 빠지면 우리 차별성(상담 중 전수 검증)의 상당 부분이 약해진다. "영향 없음"이 아니라 "축소 운용 가능"이 맞는 표현이다.

### 6.3 계약(스키마) 변경이 필요한 것

8/28 계약 동결 대상. 결정은 8장 참조.

| # | 항목 | 현재 상태 |
| --- | --- | --- |
| C1 | **위험 신호 전용 type** | `rulepack/CONTRACT_GAPS.md` 에 이미 공백으로 기록됨. `DEP-RSK-001`·`LOAN-RSK-001` 이 컴파일 금지 상태로 대기. 이벤트·WebSocket 계약에는 `risk_signal` 경보 종류가 이미 있으나(`contracts/events.schema.json`) 그 근거가 될 팩 항목을 정의할 자리가 규정 팩 스키마에 없음 |

**C1 을 `forbidden` 으로 우회하지 말 것.** 금지 발언은 은행원이 한 말이고 위험 신호는 고객이 한 말이다. 같은 축에 넣으면 고객이 "아들 계좌로 보내주세요"라고 말한 순간 화면에 은행원의 위반으로 표시된다. P6(감시가 아니라 방어 도구) 정면 위반이다.
