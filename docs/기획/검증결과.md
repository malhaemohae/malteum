# 검증 결과

기획안의 기술 가정을 실제로 재본 기록. 재현 스크립트는 각 폴더에 있다.

## 1. 문서 파싱 (2026-08-23 실측)

**도구**: OpenDataLoader PDF v2.0 (Apache-2.0) + JDK 21 · 재현: `파싱/parse_check.py`

| 확인 항목 | 결과 |
| --- | --- |
| **표 셀 복원** | 가계대출 설명서 4페이지의 **12열 표를 병합 셀까지 복원.** 전체 `table` 34개 · `table row` 210개 · `table cell` 656개 |
| **조·항 분리** | 금융소비자보호법의 항이 `list item` **545개**로 분리. 텍스트에 `제18조(적정성원칙) ①` 형태가 남아 정규식으로 조·항 코드 추출 가능 |
| 장·절 계층 | `heading` 이 `lvDoctitle`·`lvSubtitle` 레벨과 함께 출력 |
| 처리 속도 | **26페이지 약 1초.** 심사위원 업로드 경로(S4)에 충분 |
| **bbox 정밀도 한계** | `list item` 하나가 735~915자이고 bbox 가 그 전체를 감쌈. 문장 하이라이트(⑭)에는 부족 |

**왜 이 검증이 결정적이었나.** 같은 12열 표를 평면 텍스트로만 뽑으면 라벨과 값의 대응이 완전히 사라진다.

```
평면 텍스트:      ② 가산금리 / ① 대출 / 기준금리 / 리스크 / 프리미엄 / 유동성 / ...
OpenDataLoader:  ['① 대출 기준금리', '리스크 프리미엄', '유동성 프리미엄', '신용 프리미엄',
                  '자본비용', '업무원가', '법적비용', '목표 이익률', '부수거래 감면',
                  '본부조정', '영업점장 전결 조정', '= ③ 최종 금리']
```

⑤ 숫자 오류 감지는 상품 조건 수치를 **정답**으로 쓴다. 연체이자율 표처럼 구간별 수치가 있는 표에서 라벨과 값의 대응이 깨지면 잘못된 정답으로 오탐이 나고, 오탐은 P3(불확실하면 안전한 쪽)를 정면으로 어긴다. **표 구조 인식은 편의가 아니라 ⑤ 의 전제 조건이다.**

**역할 분담이 여기서 나왔다.** 구조·표는 OpenDataLoader, 인용 문자열의 문자 단위 좌표와 페이지 렌더는 pypdfium2.

## 3. STT (검증 대기)

**재현**: `stt/stt_check.py` · 테스트 음원: `stt/audio/*.wav` (Windows 내장 한국어 음성으로 생성, 계정 불필요)

| 항목 | 상태 |
| --- | --- |
| Deepgram nova-3 한국어 | 공식 문서에서 `ko`·`ko-KR` 지원 확인. **실호출 검증 대기** |
| 함께 쓸 기능 | Keyterm Prompting(도메인 용어 사전 주입) · Numerals(구어 수치 → 숫자 변환). 둘 다 한국어 지원 |
| 비용 | 신규 계정 $200 무기한 크레딧. 우리 사용량은 사실상 무료 |
| 학습 옵트아웃 | `mip_opt_out=true` 를 어댑터 기본값으로 적용 완료 |
| 폴백 | 리턴제로 VITO (한국어 특화, 월 100시간 무료) · 네이버 CLOVA Speech |

**스크립트가 재는 것은 연결 여부가 아니라 도메인 용어와 숫자 표기의 적중률이다.** `금리인하요구권`·`총부채원리금상환비율` 같은 말이 깨지면 판정 엔진이 그 항목을 아예 잡지 못한다.

```bash
pip install websockets
python stt/stt_check.py stt/audio/deposit_ko.wav --profile deposit --keyterms
```

주의: 테스트 음원은 구형 내장 음성이라 실제 상담 음성보다 쉽다. 1차 검증에는 쓸 수 있지만 최종 판단은 사람 목소리로 해야 한다.
