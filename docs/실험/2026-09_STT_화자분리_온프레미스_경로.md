# STT·화자분리 온프레미스 경로 실험 (2026-09)

## (a) 왜 했나

팀은 1차 MVP 를 **외부 STT(OpenAI Realtime) + 외부 LLM(OpenRouter qwen3-8b) + CPU Sortformer·임베딩** 조합으로 정했다. 여기서 Sortformer 는 NVIDIA 가 공개한 화자분리(diarization, 녹음에서 "몇 초부터 몇 초까지 누가 말했는가" 를 가르는 일) 모델이다. 온프레미스 경로(자체 GPU 서버에서 Qwen3-ASR + Sortformer 를 직접 돌리는 조합)는 지금 채택하지 않지만, "GPU 서버가 생기면 어댑터 교체만으로 전환된다"는 근거를 남기기 위해 2026-09-03~04 에 세션 스크래치 폴더에서 여섯 실험을 돌렸다. 이 문서는 그 실험의 수치·재현 명령·코드를 레포 안에 남긴 것이고, 실험 스크립트는 [`back/scripts/experiments/stt/`](../../back/scripts/experiments/stt/) 아래에 있다.

## (b) 시험 대상과 잣대

- **시연 음원 두 개** (은행 창구 상담 시나리오, TTS 로 제작): `preset-dep-a`(147.43초, 정답 16줄), `preset-loan-b`(127.80초, 정답 16줄). 두 화자(고객·은행원)가 번갈아 말하고 턴 사이에 무음이 있는 "쉬운" 조건이다.
- **CER 두 기준**: 정답 줄 구간에 들어오는 전사를 모아 공백·문장부호를 뺀 글자 단위 Levenshtein 으로 계산한다. "화면 표기"는 대본 원문(`text`, 아라비아 숫자·기호 포함) 기준, "발음 표기"는 구어 표기(`tts_text`, 숫자를 읽는 대로 한글로 푼 표기) 기준이다. 두 기준을 함께 보는 이유는, 모델마다 숫자를 아라비아로 내는지(ITN) 한글로 내는지가 달라 한 기준만 보면 불공정하기 때문이다.
- **핵심 용어 15개**: 우대이자율·기본이자율·과세·예금자보호·딸이 알려준 계좌(이상 dep-a), DSR/총부채원리금상환비율·무조건 승인됩니다·다른 상환방식은 안·연체가산이자율·3%(이상 loan-b), 그리고 14%·15.4%·1억·중도해지이율·차감률. 전체 전사에서 표기 변형(십사퍼센트, 일억 등)까지 허용해 검색한다.
- **화자 32줄**: 두 음원 정답 16줄씩 합쳐 32줄. 예측 화자(speaker_0/1)와 실제 화자(teller/customer)를 최적 1:1 매핑한 뒤 줄 단위로 맞았는지 센다.
- **지연 정의** (스트리밍 실험만 해당): 청크가 오디오 시각에 도착하고 GPU 하나가 순서대로 처리한다고 놓고 `done_i = max(arrive_i, done_{i-1}) + lat_i` 로 벽시계를 시뮬레이션한다. **첫 부분 전사 지연** = 첫 비어 있지 않은 텍스트가 나온 시각 − 발화 시작, **최종 확정 지연** = 발화가 끝난 뒤 텍스트가 확정된 시각 − 발화 끝.

## (c) 결과 종합표

CPU 실험(Nemotron)과 GPU 실험(Qwen)은 실행 하드웨어가 달라 속도 열을 직접 비교할 수 없다는 점에 유의한다. 표에 쓰인 용어: **seg** 는 발화 단위 입력(Sortformer 가 잘라 준 화자 구간의 오디오만 넣음), **full** 은 파일 전체를 통째로 넣는 입력, **stream** 은 발화 단위를 청크로 나눠 순서대로 넣는 스트리밍, **clips** 는 정답 줄 클립을 그대로 넣는 오라클 조건이다. **vLLM** 은 GPU 에서 LLM 계열 모델을 서빙하는 추론 엔진으로, Qwen3-ASR 의 공식 스트리밍 API 는 이 엔진 위에서만 동작한다. Qwen 계열은 실측 vLLM 스트리밍(`qwen_vllm/`)이 아니라 이 표에서는 transformers 백엔드(오프라인/시뮬레이션, `qwen_asr/`) 수치를 쓴다 — vLLM 실측 지연표는 (e) 참고.

## (d) 화자분리 결과 (Sortformer)

- `nvidia/diar_sortformer_4spk-v1`(오프라인)과 `nvidia/diar_streaming_sortformer_4spk-v2`(스트리밍) 모두 두 음원에서 **32/32줄 정확**(dep-a 16/16, loan-b 16/16), 예측 화자 수도 2로 정확했다.
- CPU 스레드별 추론 시간(v1, dep-a 147초 / loan-b 128초 음원): 8스레드 3.0초 / 2.4초, 2스레드 5.3초 / 4.3초, 1스레드 9.4초 / 7.6초. 1스레드에서도 실시간 대비 약 15~17배 빠르다. 피크 RSS 약 2.1GB.
- 위 수치는 v2 모델도 파일 전체를 한 번에 `diarize()` 로 돌린 것이다. 실제 마이크 스트림처럼 청크 단위로 밀어 넣는 저지연 호출은 별도 실험([`sortformer_chunk/RESULT.md`](../../back/scripts/experiments/stt/sortformer_chunk/RESULT.md), 2026-09-04, CPU 4스레드)으로 쟀다. 청크 15.04·4.96·2.00·0.96초 모두에서 최종·온라인 줄 정확도 32/32, 되돌림 0건, 예측 화자 수 2 였고, 라벨 지연(발화가 끝난 뒤 그 발화의 화자 번호가 처음 나오기까지)은 평균 8.16 → 3.03 → 1.27 → 0.58초, 최대 15.05 → 5.08 → 2.12 → 1.06초로 청크 길이에 비례해 줄었다. 청크 처리 시간은 0.24 → 0.11초(실시간 비율 0.016 → 0.117), 피크 RSS 1757MB. 이 음원은 화자 사이 무음이 보장된 조건이라 실제 창구 녹음에서는 짧은 청크의 정확도를 다시 확인해야 한다.

## (f) LLM 화자 추정 결과

문장 단위로 LLM(qwen3-8b/32b, openrouter 경유)에게 화자(teller/customer)를 판정시키는 실험(`speaker_infer/`, 시나리오 두 개 46문장):

| 조건 | qwen3-8b (46문장 중 정답) | qwen3-32b |
|---|---|---|
| 기존 방식(라벨 문맥 6문장) · 기존 프롬프트 | 42/46 | 44/46 |
| 기존 방식(라벨 문맥 6문장) · 보강 프롬프트("돈의 주인"·"누가 누구에게 시키는지" 단서 추가) | 43/46 | (60분 제한으로 미완주, 진행분 18/18) |
| 슬라이딩 윈도우(라벨 문맥 3문장) · 보강 프롬프트 | 44/46 | (진행분 31/31) |
| 4문장 동시 판정(joint) · 보강 프롬프트 (8b 기본값) | 44/46 | (진행분 24/25) |

프롬프트 보강(+1문장, 정확히 "해지한 돈은 딸이 알려준 계좌로 바로 보내 주세요"를 고객 발화로 정정하는 문항)이 8b 의 모든 방식에서 일관되게 정확도를 올렸고, 슬라이딩 윈도우 구조 변경 자체는 이 문제에 기여하지 않았다. 32b 는 기존 프롬프트만으로도 해당 문항을 맞혔지만 openrouter 경유 호출당 17초 이상 걸려 실시간 스트림에는 쓸 수 없다. **결론: LLM 화자 추정은 기본 신호로만 쓰고, 위험 신호(송금처·계좌·타인 지시) 검사는 화자 라벨 하나에 의존하지 않는 별도 규칙으로 이중화해야 한다 — 이번 측정에서도 8b 는 은행원 설명 문장을 고객으로 뒤집는 오답을 두 건(B11·B14) 냈다.**

## (g) 남은 격차

- **도메인 용어 오류**: `약정이율`→`약전 기율`(Nemotron·Qwen 0.6B·1.7B 공통), `정기예금`→`전기예금/전기 예금`(Nemotron·Qwen 1.7B), `상환`→`상황`(Nemotron), `결재`→`결제`(Nemotron·Qwen 0.6B·1.7B 공통), `DSR`→`디에스를`/`디에스알`/`DSL`(설정에 따라 갈림) — 파인튜닝이나 키워드 부스팅 없이는 세 모델 모두에서 남는다.
- **한글 숫자 표기(ITN 부재)**: Nemotron 은 숫자를 전부 한글로 낸다(`14%`→`십사퍼센트`). Qwen 계열은 혼합이라 긴 문맥에서는 아라비아 숫자를 내지만 짧은 발화(`15.4%`, `3%` 등)에서는 한글로 흔들리고, Qwen3-ASR-1.7B 는 full 모드에서 `1억`→`2억`처럼 금액을 바꾸는 오류를 한 번 냈다. 판정에 쓰는 핵심 수치를 그대로 못 쓰므로 어느 모델이든 한국어 ITN 후처리나 별도 검증 규칙이 필요하다.
- **단어 시각 부재**: Qwen3-ASR 계열은 모델 자체가 단어/문장 시각을 내지 않는다(별도 `Qwen3-ForcedAligner-0.6B`, 오프라인 전용). Nemotron 은 오프라인 경로에만 단어 타임스탬프가 있고 스트리밍 경로는 청크 단위로 시각을 추정해 줄 경계의 짧은 단어("네", "아")가 옆 줄로 새는 오류가 있었다.
- **OpenAI 규격은 발화 단위 전사까지만**: 1차 MVP 가 쓰는 외부 STT(OpenAI Realtime)는 발화(utterance) 단위 전사를 주는 데까지만 규격이 잡혀 있어, 이번 실험들의 화자 결합 방식(Sortformer 세그먼트에 전사를 물리는 구조)과 그대로 맞물리지는 않는다 — 어댑터 교체 시 이 결합 지점을 다시 맞춰야 한다.
