## 값이 실물이다

`rulepack` 과 `events` 의 인용 문자열·페이지·bbox 는 `03_규정문서/` 의 실제 PDF 에서 뽑았다.
`validate.py` 3층이 매번 원문과 대조하므로 **꾸며낸 인용은 커밋을 통과하지 못한다.**

```bash
python contracts/validate.py
```

근거 `span` 과 `numeric_facts` 는 실물이다. 예금자보호 1억원, 세율 15.4%, 일부해지 불가.
중도해지이율은 약정이율에 예치기간별 차감률을 곱하는 산식이라 숫자 사실을 두지 않는다.
`value + unit` 절대값 모델로는 "약정이율의 절반" 을 표현할 수 없고, 산식을 말했는지는 L1
정규식이, 내용이 맞는지는 L3(LLM) 가 판단한다(2026-09-03 팀 결정). 옛 원천(신한)의
0.10% 는 같은 날 팩·대사·판정 케이스에서 모두 지웠다.

## 시나리오 A 가 담고 있는 것 (2026-08-26 타겟 변경판: 정기예금 중도해지 상담)

시연에서 보여줄 장면이 모두 이벤트로 들어 있다. 상담은 고객의 설명 요청("지금 해지하면 얼마나 받아요?")으로
시작한다. 해지는 계약 체결 권유가 아니므로 설명의무(금소법 §19①)는 이 **설명 요청 분기**로 발동한다.

시나리오를 예금 신규에서 해지로 바꾼 근거는 현장 인터뷰(중도해지가 감사 지적 항목, 주담대가 주력 상품).
`01_기획/현장검증_인터뷰정리.md` 와 기획안 9장 참조.

이 파일은 손으로 고치지 않는다. 대본(`assets/scenarios/preset-dep-a/script.json`)을 고치고
`back/scripts/gen_scenario_trace.py` 로 다시 만든다. `supersedes` 체인이 여섯 군데 있다. 화면과 리포트는 **대체되지 않은 마지막 이벤트만** 읽는다.
`validate.py` 가 종료 요약을 이벤트에서 다시 접어 대조하므로, 접기 규칙을 잘못 구현하면 즉시 드러난다.

## id 규칙

fixture 의 id 는 `FIXT-` 로 시작한다. 실제 운영은 ULID 를 쓴다.
접두어를 다르게 둔 이유는 fixture 데이터가 운영 DB 에 섞였을 때 눈으로 바로 구분되게 하려는 것이다.

## 판정 케이스가 고정하는 것

`judge_cases.json` 은 통과·실패만 보는 표가 아니다. 각 케이스의 `why` 가 **왜 이 동작이어야 하는지**를 적어 둔 것이고,
그것이 나중에 "이건 왜 이렇게 돼 있지" 를 막는다. 특히 다음 네 개는 하나라도 깨지면 제품이 못 쓰게 된다.

- 인용된 금지 표현은 위반이 아니다 (화자를 보지 않으면 즉시 오탐)
- 숫자가 맞으면 경보가 없다 (오탐이 쌓이면 은행원이 경보를 무시한다)
- 화자 신뢰도가 낮으면 met 로 올리지 않는다 (잘못된 met 가 잘못된 unmet 보다 위험)
- 근거를 못 찾으면 답하지 않는다 (없는 근거를 만들면 그게 제일 나쁜 실패)
- 위험 신호(risk)는 고객 발화만 보고 verdict 없이 경보만 만든다 (고객의 말이 은행원의 위반으로 표시되면 P6 위반)

`tier` 와 `max_ms` 는 성능 계약이다. L1 5ms, L1+L2 20ms, L3 1500ms.
