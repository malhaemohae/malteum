## 웹 스냅샷 원천

원천은 은행이 배포한 PDF 가 원칙이다. 2026-09-05 에 처음으로 예외를 두었다. 신용대출 구비서류는 하나은행 배포 PDF 어디에도 없고 상품 공시 웹페이지에만 있어서, 그 페이지를 headless Chrome 으로 PDF 인쇄한 스냅샷을 원천 08 로 넣었다.

허용 조건. 셋을 모두 만족해야 웹 스냅샷을 원천으로 인정한다.

| 조건 | 이유 |
| --- | --- |
| 같은 내용을 담은 은행 배포 PDF 가 없음을 확인하고 어디를 뒤졌는지 적는다 | 배포 PDF 가 있으면 그쪽이 늘 우선. 08 은 대출 설명서 PDF 3종(가계대출 2025.01 · 권유용 2025.01 · 은행대리업용 2026.07)과 서식자료실을 뒤진 기록이 `STATUS.md` 최근 변경에 있음 |
| 페이지에 준법감시인 심의필 번호와 유효기간이 있어야 함 | 그것이 있어야 상품설명서와 같은 공시물로 볼 수 있음. 홍보 배너나 FAQ 는 원천이 아님 |
| 원본 HTML 을 같은 이름(`.html`)으로 PDF 옆에 함께 둔다. 재스냅샷 때는 **교체**하고 쌓지 않는다 | 같은 URL 을 다시 인쇄하면 바이트가 달라 해시로 재현할 수 없음. 검증자는 HTML 본문과 PDF 문구를 대조함. HTML 해시는 그날의 `source_refresh_*.json` 에 적음 |

절차. 인쇄 명령은 이것이고, 표의 상태 칸에 `스냅샷 YYYY-MM-DD` 를 적으면 `source_manifest.py` 가 그 원천만 그 날짜를 `snapshot_date` 로 쓴다.

```bash
curl -sL -A "Mozilla/5.0" "<공시 URL>" -o assets/03_규정문서/08_상품공시_BEST신용대출.html
chrome --headless=new --disable-gpu --no-pdf-header-footer --virtual-time-budget=8000   --print-to-pdf=assets/03_규정문서/08_상품공시_BEST신용대출.pdf "<공시 URL>"
```

재확인. 웹페이지는 새 파일을 올리는 것이 아니라 제자리에서 바뀌므로 해시 비교로 갱신을 잡을 수 없다. 분기마다 같은 URL 을 다시 받아 HTML 본문의 `필요서류` 문구를 보관본과 대조하고, 심의필 번호가 바뀌었으면 새 스냅샷으로 교체한다(교체 절차 그대로, 새 팩 버전). 공시 유효기간 만료일(2027-11-30)은 `source_audit.json` 의 `reason` 에 적어 두었다.

## 교체 절차

1. 원천 담당자가 공식 URL 과 문서 시행 또는 심의 유효기간을 확인한다
2. 승인된 PDF 로 `assets/03_규정문서/` 의 대응 파일을 교체한다
3. `MANIFEST.md` 의 문서 링크 · 규모를 갱신한다
4. `python -m rulepack.cli build` 를 돌린다. page · span · bbox 가 바뀐 후보는 자동 통과시키지 않고 재검토한다
5. `config/source_audit.json` 의 후보별 `source_sha256` 과 판정을 새 원천 기준으로 갱신한다
6. 감사 기록을 새 날짜 파일로 남긴다(`artifacts/source_refresh_<YYYYMMDD>.json`). 기존 파일은 그날 판단의 근거라 고치지 않는다
7. `verify --strict` · 전체 테스트 · `contracts/validate.py` 를 통과시킨다
8. 업무 승인자가 RC(Release Candidate: 발행 전 검토 후보)를 검토하고 서명 승인한다

## 2026-09-05 교체 기록 · 원천 08 추가

BEST 신용대출 상품 공시 웹페이지 스냅샷을 원천 08 로 추가했다.

- 하나은행 배포 대출 설명서 PDF 3종(가계대출 2025.01 24쪽 · 권유용 2025.01 6쪽 · 은행대리업용 2026.07 11쪽)에서 구비서류·필요서류·재직·소득증명 검색 0건. 서식자료실 대출 서식은 기업 여신·보금자리론 서식이라 신용대출 구비서류 없음
- 공시 페이지 p.2 에 `필요서류 소득증명서류 / 재직증명서(급여소득자) / 사업자등록증(사업소득자)`, p.3 에 심의필 제2025-상품공시-1055호(2025.12.26)와 유효기간 2025.12.26~2027.11.30 이 `find_span` 으로 실재 확인됨
- `LOAN-DOC-001` 의 근거를 06 p.3 "자필로 기재" 에서 08 p.2 "필요서류 소득증명서류" 로 바꾸고 `source_audit.json` 을 08 해시로 갱신. 검토 대기 해제, `LOAN-2026.08-v6` 발행
- 되돌아온 판단: 처음에는 "우리가 만든 파일의 해시라 원천 고정이 약해진다" 며 웹 스냅샷을 기각했음. 해시가 지키는 것은 가져온 뒤 바뀌지 않았다는 사실이고 출처 진위는 URL·심의필·스냅샷 일자가 지킨다는 점에서 기존 PDF 원천과 같아, 위 허용 조건을 붙여 채택

## 발행 경계

- 이 파이프라인의 정상 종점은 RC 와 리뷰 큐다. 운영 팩을 자동 발행하지 않는다
- `confirmed` 만으로 발행되지 않는다. 근거 검증 · 서명 승인 · RC digest 검증을 모두 통과해야 한다
- 감사 레코드는 로컬 원천 PDF 의 SHA-256 과 묶인다. 해시가 어긋나면 `source_audit_hash_mismatch` 로 차단된다
